# 工具调用同轮正文发送验收

2026-10-19，Agent 5.6.0、Conversation 5.2.0、Delivery 0.9.0 已切换到当前实例。RuntimeGraph 53，Bot ONLINE，25/25 模块 ACTIVE。原有唯一只读观察器已恢复。

Agent 将经过原生协议及工具参数校验的非空正文投影为 `assistant.message`，与 ModelTurn 在一个 UnitOfWork 中提交发送意图。Conversation 提供已领取触发所属的绑定与频道路由；Delivery 通过自己的受限 participant 创建 CHAT 意图。最终回复共用原有会话 CHAT 通道，中途发言不终结触发，不在最终回复中重复拼接。thinking 与无效候选不进入发送投影。

本地模型/配置检查 49 项通过；协议、包声明与 Delivery 端口检查 20 项通过，Ruff 通过。隔离 PostgreSQL 完整 BotHost 检查已验证：后续模型调用被阻塞时，中途正文仍已发到模拟平台；解除阻塞后最终回答作为第二条消息发送；原生 reasoning 与 tool_call_id 继续用于模型续轮，推理不出现在公开消息里。工具准备后强制终止 Agent Worker，使用原制品目录恢复，最终只有一份中途意图及一次模拟发送，Run 的工具过期失败不重新发布已发送正文。

最终隔离回归为 4 passed（441.14 秒），包含上述两个场景、普通最终回答以及 Delivery 发送意图事务检查；模拟平台未向任何真实群发消息。

本次只更换两个模块的函数定义与对应存储基线身份，表定义和业务行均保留；没有增加运行时迁移或双协议兼容代码。维护事务事先比对新旧制品，确认差异限于三个指定函数，再与三个制品选择一并提交。三个组件的期望配置修订及内容摘要在前后核对一致，原有发送回执保留。真实 QQ 的新行为尚未单独验收，不能将模拟发送检查等同于实际群呈现。
