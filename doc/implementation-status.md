# Forest 当前实现状态

更新日期：2026-09-23。

> 本页只记录当前工作树事实，不定义目标架构。发生冲突时依次以 [00 架构总契约](00-architecture-contract.md)、[13 微内核控制面重构](13-microkernel-control-plane-redesign.md)、[14 干净 Schema 与载荷来源](14-clean-schema-and-payload-provenance.md)和[15 单 Agent 生产执行](15-single-agent-production-execution.md)为准。Forest 尚不可发布。

## 不可改变的当前语义

- Agent 是 `agent.runtime` 模块中的单会话状态机，不存在产品子 Agent。
- 每群至多一条活动 Agent 响应链；群之间可以并行。新触发在下一次模型调用边界接入截至最后一个触发的连续消息前缀，普通尾部在终止后静默排空。
- 每个 Bot 只有一个全局记忆域，每个群是一条独立主干；联想可以跨主干，召回必须携带来源群和作者。
- 裁剪不调用 LLM，也不生成记忆摘要。文本与图片均进入权威载荷、嵌入和检索；text-only Provider 只在单次请求投影中移除图片。
- `conversation.scheduler` 已实现持久 ContextView 裁剪：lane 维护活动/归档单元计数，高水位时在 Actor 事务内发布不可变 `context_compactions` 与逐单元 `context_compaction_units`，保留原 `context_units`、作者、群来源和多模态 Payload 不变。`context_snapshot()` 只读取活动单元和一个机器可读归档引用；策略由该模块自己的 WebUI 配置贡献管理。当前请求只把实际 trigger 原文设为不可裁剪，触发前的同批普通消息仍进入 canonical Context 并参与正常预算裁剪。
- VL 嵌入空间与 Bot 生命周期绑定，只允许更换兼容 endpoint 或凭据。
- WebUI 壳只负责身份、作用域、模块发现和受控工作区；业务页面、schema、查询和动作由准确模块 Generation 贡献。
- 未发布结构直接删改并重建开发数据库，不新增迁移、兼容读取、双写、旧 API 转发或 fallback。

设计文档已经先于后续代码完成语义纠偏：00 明确列出被废止的 Bot/Agent 中心组合根、产品子 Agent、固定业务后台、模糊记忆关系、第二套执行链和开发期兼容迁移；10 固定百万级来源的服务端组合筛选、快照键集分页与可解释关系 DTO；12 固定 PC 工作台的有界 pane 布局和模块 UI 尺寸协议。仍存在的旧代码和旧页面均列入删除范围，不能反向解释这些目标契约。

## 仍阻塞发布的插件架构缺口

`PackageGenerationAdapter` 已闭合不可变 `PackageSnapshot`、隔离 `PythonWorker` 与 `RuntimeModuleRegistry`/`kernel.runtime` Generation 的生产路径。`conversation.trigger-policy`、`codec.onebot` 与 `provider.chat-completions` 已成为真实 builtin 包，携带 manifest、配置/输入/输出 schema 和 Worker 入口；旧 `clean_provider_module.py`、`clean_provider_runtime.py` 已物理删除。Provider 包的 Worker 只冻结公开 profile/能力快照，manifest 声明的 `provider.model.dispatch` 由 Generation 专属 `chat-completions.http` 效果驱动实现；Secret 和 HTTP client 不进入 Worker。效果驱动与 Worker 共同 start/quiesce/resume/close，候选启动失败会同时回收两者，服务在途计数与持久操作账本覆盖外部效果调用。Adapter 通过冻结 contract route 调用准确 Codec Generation；Codec 不持有 Binding、凭据、网络客户端或业务状态，Adapter 在产生外部效果前独立复核 action、wire 摘要和允许的 segment。跨 Worker 调用现已显式分离稳定业务 `operation_id` 与单次执行 `call_id`；Router 传递冻结 route 和 invocation，嵌套调用记录父调用且只能缩短父 deadline，缺少调用身份的插件端口直接拒绝。候选 Worker 和效果驱动在 route 发布前完成准备、启动和健康检查，本地 admission gate 保持关闭；旧 Generation 先冻结并排空，持久 route 提交后新 gate 才同步打开。失败发布会先恢复旧 Worker/驱动，再恢复旧 gate；ACTIVE Generation 不允许绕过 QUIESCENT 直接清理。

插件宿主已删除读写合一的 `PackageCapabilityGateway`。State Query 与 State Command 分别由 `PackageStateQueries`、`PackageStateCommands` 端口和独立宿主对象承载；Adapter 构造时分别取得端口，缺少包所声明的任一端口会在描述符编译阶段失败。写入事务同时完成当前 Generation 成员围栏、稳定操作重放、key 级串行、revision CAS、受管 Payload、不可变 step 与 head 推进。相同操作跨执行尝试返回原回执，输入变化明确冲突；同 revision 并发写确定地只有一个成功。获得副作用能力的插件服务现在先进入持久 `service_operations/service_call_attempts`：稳定 operation 固定输入与因果根，每个 call 固定准确 Generation/Worker/图/父调用/deadline，最多一次 Worker 派发，成功或失败终态保存为 Payload 并可跨 call 重放，过期无终态只落 `UNKNOWN`。Adapter 排空覆盖账本准入、Worker 和终态提交。纯 Codec/Trigger 不写账本。真实 `forest.counter` 包已在隔离 Worker 与完整 RuntimeGraph 中证明重复服务 operation 返回原结果且状态只推进一次。Event 与 ComponentJob 不再伪装成 Gateway 回调，而是通过 package runtime contract 中声明的两个冻结 routing 服务句柄进入独立 authority。

包级 Event subscription 与 ComponentJob 使用不同的封闭 contribution、内容寻址 handler service 和 Worker 投递协议；PackageAdapter 只持有冻结的 `routing.event.publish/1`、`routing.component-job.schedule/1` 服务句柄，不持有 routing Repository。双向运行关系不进入启动 DAG：发布/调度组件单向依赖 `routing.graph` authority，dispatcher 到 handler 依靠持久 claim 和冻结 Contract Route。Registry 已实现描述符声明的两阶段 owned-work 排空；局部 Generation 激活不开放领取，整张图 ACTIVE 且 Router 开放后才由 Registry 统一打开 owned-work gate。失败恢复先恢复模块和本地门，最后开放持久 graph admission，FAILED/STOPPED 的半恢复图不能重新接纳工作。Event/ComponentJob 没有映射到通用 `job.scheduler`。

`routing.graph` 的干净存储 baseline 已定义不可变 Route publication、发布/订阅/ComponentJob 路由、Event 与逐订阅 delivery/attempt、ComponentJob 与逐次 attempt；数据库 trigger 封闭 delivery、Job 和 attempt 的合法转移。claim 现在同时保存 routing 所有者 Generation 与目标插件 Generation，结算必须匹配 token、attempt、routing Generation、目标 Generation 和未过期 lease。过期且无法证明外部结果的 attempt 只进入 `UNKNOWN`，不自动重复副作用。目录发布、Event 和 ComponentJob 分属三个 Command authority，共享层只有不可变 Route/Claim 值。

`routing.graph` 生命周期模块已进入生产 RuntimeGraph 组合：图 publication 事务冻结 publisher/subscriber/ComponentJob 的准确 Generation、schema 与 handler；Event Command 原子保存受管 Payload、Event 和完整逐订阅 delivery；ComponentJob Command 原子保存输入 Payload 和延迟任务。稳定 operation 摘要不含 graph/Generation/Route，首次执行冻结这些事实，换代恢复返回原 Event/Job。dispatcher 通过当前图的稳定 route 领取旧队列，调用准确目标 Generation，并以分离的成功/失败 Command 结算。独立 Docker 网络中的 PostgreSQL 17 探针已实际完成空库安装、目录发布、Event/Job 创建、routing Generation claim、成功结算和 Event 重放；第二个真实 `kernel + routing.graph` RuntimeGraph 探针完成全图发布、统一 owned-work 开门、替换冻结/排空、失败恢复、关闭和任务回收。当前尚未增加 routing 管理 Query/UI，生产图中也还没有一个真实 builtin 包声明 Event/ComponentJob 用于端到端业务验收。

该路径已经以真实 Worker 进程和临时 PostgreSQL 验证：包入口未进入宿主 `sys.modules`，候选 gate 在发布前拒绝调用，调用结果携带精确 Generation，排空/恢复/再次激活后仍由同一生命周期管理，最终 Worker 进程退出；真实 RuntimeGraph 能安装、发布并关闭包 Generation。验证只作为这些跨进程与事务边界的实现证据，不替代架构不变量。

其余 Agent、Memory、Embedding、Vector Index、Adapter transport、Shell、Job、Delivery 等组件仍由宿主 `bootstrap_clean_*` 构造，因此整张生产图仍不是可安装插件图，当前实现仍禁止发布。迁移阻塞按机制分为两类：Agent、Memory、Conversation、Shell、Job、Delivery 与 routing 需要包级 domain Query/Command 和 UnitOfWork participant；Embedding、Vector Index、Adapter transport、Media 与 Process Executor 需要按 Provider 已采用的包级 `effect_service` 模式接入 Secret lease 和受限 Effect executor。它们必须经过同一 Package Generation 路径迁移并物理删除旧宿主实现，不增加总 Gateway、shim、fallback、双写或第二套生命周期，也不以改 Python 导入路径冒充插件化。

## 已落地但尚未接入插件 Worker 的运行时切片

### 最小 Bootstrap 与五个内核模块

`forest_kernel` 只保存 Bot 身份和 schema bundle 账本。以下模块各自拥有独立 namespace、baseline、Repository、模块配置和真实 grant set：

- `kernel.runtime`
- `kernel.payload`
- `kernel.authorization`
- `kernel.effect`
- `kernel.audit`

`bootstrap_clean_kernel()` 可以从空数据库安装这五个模块并把它们作为普通 Generation 发布，不依赖旧 `public` 业务表。

### 精确 Generation 与 RuntimeGraph

干净 Registry 已执行以下固定协议：

1. `prepare_generation` 冻结包、配置、授权、存储和状态契约；
2. `kernel.runtime` 持久化候选图并分配精确 `generation_id`；
3. `bind_generation` 把数据库分配的身份交给模块；
4. `start` 只预热待命资源；
5. 模块 publication participant、配置 effective、Generation ACTIVE、Route 和 graph head 在一个 Bot 数据库事务中提交；
6. `activate_generation` 只打开本地 admission gate，不执行 I/O；
7. 关闭先原子冻结所有 route admission，保留当前 graph head 供已持 lease 的工作以 member fence 排空；逆依赖达到 QUIESCENT 后才撤下 head并落 STOPPED/FAILED。

同一 HostLease 下的热替换主链已经改为先排空再发布：候选图及其 OneBot 客户端先在 `BUFFERING` 状态预热但不取得路由；旧图随后原子冻结 DATA/CONTROL 顶层准入，并按反向依赖顺序排空仍拥有持久工作的可恢复 Worker。Conversation 会在下一次模型或工具外部调用前观察排空信号，在已有持久边界释放 Run/actor；确认排空后 RuntimeGraph publication 事务才把旧图/旧客户端置为 `RETIRED/RETIRING`、切换准确 Generation route 与 Binding epoch，候选连接随后打开事件流。候选在发布前失败时，authority 恢复旧图原声明的准入位和 route epoch，本地 Worker 按正向依赖顺序恢复；发布成功后旧 Adapter、Provider 与 Registry 才关闭并记录 `STOPPED/DISPOSED`。宿主用单一替换锁串行这些阶段，配置 revision 可在不停 HostLease 的情况下生效。

新工作通过 `verify_active_generation_in()` 在最终事务内复核准确组件、Generation、RuntimeGraph、Route epoch 和 DATA/CONTROL admission；已经领取的排空工作只能通过 `verify_generation_member_in()` 继续，并同时复核自己的 actor/run/call lease。绑定身份失败、预热失败、图提交失败、本地 activation 不变量失败和 freeze 后新准入拒绝都有回收测试，不会遗留可接纳工作的部分图。

### Provider、Agent、Conversation 与 OneBot Messaging 图

> **生产接线状态：** Conversation Worker、单 Agent 执行、Context 投影、Provider 调用、最终回复与 Session 交接已经进入同一干净 RuntimeGraph。Agent→Provider 与 Conversation→Agent 使用冻结到准确图/代际/契约版本的 Contract Router 句柄；Conversation 只调用输入选择、最终回复和 Session 交接三个内核 UoW 服务，Agent、Conversation、Memory、Delivery participant 由内核按声明解析。生产模块不再通过共享模块字典、直接运行实例或 bound participant 完成这条链。PostgreSQL 集成测试已从真实 OneBot 入站事实自动生成回复、原子提交 Context/SendIntent、经 Delivery 发送并静默关闭 Session。
当前候选 RuntimeGraph 共 19 个成员：五个内核模块，以及 `provider.chat-completions`、`embedding.multimodal`、`vector.index`、`memory.graph`、`media.capture`、`agent.runtime`、`conversation.scheduler`、`conversation.trigger-policy`、`codec.onebot`、`adapter.onebot`、`delivery`、`process.executor`、`job.scheduler`、`shell.command` 十四个平级业务模块：
- `provider.chat-completions` builtin 的 Worker 独占公开 profile/模型能力快照；Agent 按该快照完成单次 `ModelInputProjection`，Provider Generation 的受限效果驱动独占端点、Secret 解析与 HTTP client。每个请求绑定精确 Provider Generation 与能力摘要；Agent→Effect 的事务同时提交授权票据消费、RuntimeGraph fence、Effect handoff 与 Agent attempt handoff，驱动在实际 HTTP 发送前再次复核 Effect 和 Generation；
- text-only Provider 的请求投影会递归移除图片、受管媒体 URL/base64/file 字段，同时保留作者、来源群、trigger 与不可见模态标记；该投影不修改权威多模态 Context；
- `agent.runtime` 的全部状态变更经准确 Agent Generation 在最终数据库事务内复核；
- Agent `COMPLETED` Run 不再擅自关闭 Session；Conversation 排空决定显式关闭，或在同一 Session 下原子推进唯一后继 Run；
- `conversation.scheduler` 的接纳与分类端口检查自身准确 Generation；
- `adapter.onebot` 只拥有 Binding、配置修订、客户端代际、平台事件、网络客户端和 OneBot transport；
- `codec.onebot` 在隔离 Worker 中执行纯规范化与发送编码，通过 schema 和 Adapter 最终 wire guard 双重约束输出；
- Adapter 不拥有 Conversation lane、Shell、Agent、Memory、Delivery 或发送账本；
- Delivery 已有独立 schema、配置、grant set、Generation、Repository、`DeliveryAuthorizationPort` 和生命周期所属的发送 Worker，依赖 Adapter 的公开 transport-fence 端口与 Kernel Effect 端口，不读取 Adapter 私有表。Worker 从持久队列领取 part，将不可变业务载荷投影成 OneBot wire，在交接前写入 Effect permit 并复核当前 Binding/Adapter Generation；网络交接后只接受 `SENT`、明确 `NOT_SENT` 或 `UNKNOWN` 观察。重启时，过期 `PREPARED` attempt 会经 Effect abandonment 回到队列，过期 `DISPATCHING` attempt 只能落为 `UNKNOWN`，不能猜测未发送或自动重发。动态 part 不再诱导内核创建逐 part grant，`delivery.send` 票据绑定 Bot 能力、part semantic digest、精确 binding plan 与 Adapter Generation，最终 operation 的单次消费仍防止跨 part/参数重放。
- `kernel.effect` 的 fence verifier 已按 `fence_kind` 注册且禁止覆盖；工具走 `runtime.graph`，Delivery 走 `adapter.binding`。Adapter 从持久 client incarnation 反查 binding、generation、epoch 与 fence digest 后再复核当前 head，调用方不能自行拼出一张连接 fence。
- OneBot 客户端先以 `BUFFERING` 绑定配置 revision、Adapter Generation 和 executor fence；
- Binding client publication 作为 RuntimeGraph 事务 participant，与 Adapter Route 一起提交；
- WebSocket 在预热期只缓存，图提交后才打开事件流；
- 旧 Adapter Generation 即使仍持有 Binding epoch，也不能接纳事件或发送；
- raw event、normalized parts 和 author snapshot 先成为带来源闭包的 payload；文本消息再生成独立 UTF-8 Memory part，由一个调用方 UoW 原子提交 Adapter platform event、Conversation Inbox、群主干和 Memory occurrence；
- Binding head、client 和事件接纳已统一锁序，同一账号不同群可以并行。

lane。`conversation.scheduler` 只拥有调度权威；生命周期 Worker 经冻结的 agent.execute/1 句柄调用单一 Agent 状态机，并把最终回复与 Session 交接交给内核 UoW 服务。内核协调器按声明解析 participant，业务模块不持有其他运行实例。PARSING、REPAIR_READY 和 SAFE_BOUNDARY 已支持从持久事实确定性自动重放；RuntimeGraph 现从各模块描述符汇总工具贡献并拒绝全图重名，`agent.runtime` 只消费受限目录和冻结服务句柄。首个只读 `runtime_status` 工具由 `kernel.runtime` 自身贡献，已贯通真实模型调用、授权、Effect、工具所有载荷和结果查询重放。WAIT_APPROVAL 现由跨模块事务先锁定批准对象，再写入带 approval_ref 的精确持久阻塞；批准提交后只提前唤醒匹配的 Conversation，若决定抢先提交则 Worker 在同一 actor 内立即续跑，进程丢失仍由恢复期限兜底。热替换现用 lifecycle activation ID 把旧 Worker 的安全点交接持久化为 `RELOAD_WAIT`，记录原执行阶段和检查点，候选发布或发布失败恢复旧图时只以同一 operation 精确释放 Agent 与 Conversation 阻塞；新宿主启动后也会回收崩溃遗留的交接等待。目标设计不增加拥有聊天语义的生产执行模块。

当前真实网络模块支持正向 Universal WebSocket 与 HTTP action 客户端，启动时调用 `get_login_info` 校验账号。HTTP 上报通过模块端口接入，尚未接入新的生产 Web transport 宿主。

`memory.graph`、`embedding.multimodal` 与 `vector.index` 已作为三个独立成员进入干净 RuntimeGraph。Memory 独占图 schema、facet/claim、预算、稳定 `index_ref_id`、召回语义和删除 outbox；Embedding Provider 独占 profile identity、endpoint/凭据、请求投影、HTTP 客户端、传输尝试和用量/结果载荷；Vector Index 独占 Milvus client、Bot collection 身份与 ANN 查询。Memory 的生命周期 Worker 只持有冻结的 `embedding.encode/1` 和 `vector.index.upsert/search/delete` 服务句柄，其他两个模块均无法读取 Memory 私有表。Embedding 成功先把 facet 结算为 `EMBEDDED`，以相同 ref 幂等发布 Milvus 成功后才转为 `READY`；召回只接收候选 ref，并在 PostgreSQL 快照中重新验证来源、资格、空间与删除状态。默认冻结 QiYu 使用的 `Qwen/Qwen3-VL-Embedding-8B`、4096 维 L2 空间；Bot 首次初始化后模型、维度和向量空间由 Provider/Memory/Vector Index 三重拒绝变更，endpoint/凭据/连接参数可经配置 plan/apply 和新 Generation 替换。`memory.recall/1` 把精确 InputBatch 物化为 `QUERY` facet；只有 Scheduler 已提交的确定性 archive 才把源从 `REGISTERED/ADMITTED` 提升为长期 `ELIGIBLE` 并创建 DOCUMENT facet。Milvus 只选直接种子，随后按 QiYu 的最大乘积路径扩散时序/联想图；每节点联想边超过配置上限时按查询种子伪随机抽样后再扩散。检索包、关系区域和实际模型投影回执保持不可变，Evidence 逐项标注原始群聊、主干、作者、直接种子和路径。Memory 另贡献 `memory_recall_exact` Agent 工具，按稳定 source ID 绕过 ANN 精确读取已归档单元。

Embedding 批处理现先完成本地分面物化和输入校验，再预留每日预算；交接前失败会将已领取 attempt 明确结算为 `NOT_SENT`，不会遗留 `PREPARED` attempt 或 `RESERVED` 预算。纯空白文本和超过单图上限的图片会保留为可查询的 `SUPPRESSED` facet，不进入 Provider；批次领取同时限制累计图片字节。单批数据、Provider 或存储错误只使 Worker 有界退避并公开最近错误，不再结束模块所属任务，下一轮仍会执行过期 attempt 与预算恢复。

`media.capture` 现已作为独立 Generation 进入生产图。Adapter/Conversation/Media 四参与者 ingress UoW 原子登记图片任务，规范 Context 只保存稳定 `media_ref`，临时 URL 仅留在 Media 私有 schema。生命周期 Worker 使用租约、重试和资源上限下载并验证图片，把像素保存为 Kernel Payload 后通过 Memory 公共端口发布保持原始段序的 TEXT/IMAGE parts；InputBatch 或 archive 先于图片完成时分别保留 pending admission/archive，来源完成后按顺序收敛，最终失败使两类待定事实显式成为 `UNAVAILABLE`。当前 Context 图片由 `media.context.resolve/1` 在模型调用边界物化，历史图片由 EvidenceBundle 物化，二者均使用来源绑定的 `MediaSnapshot`。

`shell.command` 现已作为独立 Generation 和生命周期 Worker 进入同一生产图。稳定 ShellGate 在业务触发前只识别直接 `#forest` 前缀；规范参数、未知命令和拒绝载荷均写入受管 Payload。Adapter、Conversation、Memory、Media、Shell 与拒绝回执由一个入站 UoW 原子合流，因此控制消息仍进入带真实作者的群 Context 和全局记忆，但绝不回退给 Agent。命令目录由各模块通过 `RuntimeModuleDescriptor.shell_commands` 贡献；通用解析器从参数 schema 生成语法，Contract Router 为 `shell.command` 解析准确贡献 Generation 的服务句柄，Shell 本体不含 `core.status` 等命令分支。命令 registry 与管理员策略在 RuntimeGraph publication 事务中绑定准确图、目标 Generation、schema、能力摘要及服务 owner；执行前及提交结果前均重验当前策略、Binding fence、route fence 和一次性 `management.invoke` 票据。P0 claim 先于 P1，CONTROL SendIntent 独立于 CHAT；`core.pause/resume` 由 `kernel.runtime` 贡献的类型化命令服务通过 `maintenance_epoch` CAS 关闭/恢复 DATA admission，关闭期间普通消息不会落业务事件，而 Shell 接纳、`core.status`、`core.resume` 和回执仍可完成。`kernel.audit` 自己贡献 `audit.tail` 及查询服务，支持动作、生产者、来源、资源、操作和稳定游标筛选；Shell 只能经其准确 Generation 端口读取脱敏元数据。每次 Shell 终态、CONTROL SendIntent 与不可变审计 envelope 在同一短事务提交，投递参与者失败时三者整体回滚，重放使用稳定 audit ID 收敛。策略在排队后撤销会以无管理效果的安全失败事实、审计及 CONTROL 回执收敛，不会杀死整个 Worker 或把失败记录伪装成一次获准执行。

`job.scheduler` 现已作为独立 Generation 进入生产图。任务类型由执行模块以 `RuntimeJobTypeContribution` 发布版本、输入 schema、服务、超时、最大尝试和并发约束；Scheduler 通过冻结的 Contract Router 句柄调用准确执行 Generation，不读取或硬编码业务任务。其私有 baseline 保存幂等入队、单调 revision、租约 token、尝试次数、取消意图和不可变终态，任务输入与结果正文由 `kernel.payload` 保存并保留父链。并发 claim 使用 `FOR UPDATE SKIP LOCKED`，旧 claim 的完成会被 token fence 拒绝；租约耗尽而无法证明结果时落 `UNKNOWN`。群聊 `jobs list/inspect/run/cancel` 与模块自带 Web 工作区共用这一 authority；Web 查询支持状态、类型、请求主体、快照和复合游标。首个真实贡献者是 `kernel.runtime` 的只读 `runtime.health-snapshot`，用来验证完整目录、路由、Worker 与结果载荷链。

`process.executor` 以独立 Generation 贡献 `native.execute`，并复用上述 Job 权威链。管理员只能选择模块配置中预登记的 ExecutionProfile 并提供受 profile schema 约束的参数；可执行文件绝对路径和 SHA-256、argv 模板、工作目录、固定环境、网络策略、CPU/内存/墙钟/文件/进程/输出上限均由模块配置冻结。执行不经过 shell；每次启动重新验证只读常规文件和摘要。Linux `deny` 网络策略通过 seccomp 拒绝 socket 系统调用，不可用时整个 Generation 拒绝启动而不会静默降级。取消和超时先终止进程组再强制杀死；stdout/stderr 有界采集到 `kernel.payload`，Job 结果只携带摘要、长度、截断标记和 Payload 引用。

### 已有干净业务 Authority

以下模块均有独立官方 baseline、Repository 和定向 PostgreSQL 测试；其生产接线范围以上文逐项说明为准：

- `memory.graph`、`embedding.multimodal`、`vector.index` 与 `media.capture`：生命周期 Worker、Bot 级冻结语义空间、Milvus 派生向量索引、稳定 ref、每日请求/Token 预算、每群主干、图文来源摄入、archive-only 长期资格、最大乘积图扩散、高出度联想抽样、成功回复关联 journal、Agent 向量召回与精确 ID 工具、当前图片投影及跨主干关系查询已进入 RuntimeGraph；

Repository 测试证明各自权威状态机；生产启动链是否切换只按上文列出的 19 成员 RuntimeGraph 与集成测试判断。

- 旧 RuntimeGraph store、`legacy-module-factory/1` 及第二套启动/回滚状态机；

可执行 CLI 现发布生产入口 `forest supervisor`、显式诊断入口 `forest bot` 与离线 `forest plugin init/check/build/lock/export/import`。会启动旧固定业务后台的 `forest serve`、调用旧迁移 Kernel 的 `forest dev`、旧 setup/recovery 命令均已从命令面删除；控制台由准确作用域的模块贡献承载。插件 watch 将在接入同一 Generation publication 协议后重新提供，不能复活旧开发宿主。
