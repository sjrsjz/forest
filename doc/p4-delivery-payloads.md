# 输入、原图与发送正文迁移（029–035）

这是内部载荷存储切换的实现记录，不代表公开的完整遗忘功能已经交付。其他仍保存正文的业务族必须完成迁移后，才能对外给出完整删除保证。

## 正文与效果事实

029 将 Inbox 的完整作者信息和有序消息段、私有图片来源 URI、旧图片捕获的原始字节及来源清单迁入 PayloadStore。原 Inbox.author 只保留鉴权实际使用的身份字段；原 segments、source、content、source_manifest 列必须为空。读路径通过 InputContentStore 加载正文，不回退读取旧列。媒体仍保留原图，未转换成文字描述。

033 将 SendPart 的有序内容、SendAttempt 的精确 HTTP 字节、完整平台回执及人工裁定原因移入 PayloadStore。平台目标、分片顺序、operation 身份、语义和 wire 摘要、发送状态与 UNKNOWN 事实仍留在效果账本。回执的 message_id、status、retcode、error_code 通过有限字段和类型投影保留，以便处理平台 echo 与管理状态；任意嵌套回执正文仅存在于受管载荷中。

新群聊回复以正式 Reply payload 为发送父项，群聊控制回复以命令 Inbox payload 为父项。精确请求继承 SendPart，完整回执继承该请求。可信宿主主动生成、确实没有输入依赖的独立通知允许没有 parents；Agent 或命令派生结果不能使用这一入口省略已有来源。

## 删除与晚到结果

领取发送任务前检查正文可用性。适配器转换完成后，发布发送许可再次检查固定的删除 epoch 和来源依赖；进入 HTTP 前还检查一次未使用许可及精确受管字节。删除不会让已移除内容被新的发送请求使用。因未消费许可的正文检查失败而没有进入网络的任务记录为 NOT_SENT；网络已开始后的超时、取消或结果丢失仍保留 UNKNOWN。

原 owner 的晚到结果仍可以记录 SENT 或 UNKNOWN。这条观察路径只依次锁定分片、attempt 和 memory clock，不取得新的 Host、Actor 或发送权限。若原请求依赖已经不可用，只保留白名单效果元数据，不创建完整回执载荷，也不恢复请求字节。对已删除的 UNKNOWN 内容不能用 NOT_SENT 裁定重新发送；仍可明确 SKIP 释放后续顺序。

旧 MediaStore 的存储占用按实际仍存在的捕获 body 重新核算，持有 quota 锁和 memory clock。已撤销但尚未 scrub 的字节继续占用配额；物理删除完成后，下次保存能够复用空间。

## 升级和限制

035 为平台回执精确证明的自身回声登记不可变来源关联。证明同时核对 Bot、Binding 固定账号、会话及线程、SENT attempt 的 message_id、同一 SendIntent，以及正式 Reply 或已完成群聊命令；不会按文字相同推测关联。关联指向该 attempt 的受管原始请求，所以原始输入、正式回复和控制输出的删除都能传到回声 SourceUnit、Inbox 与发现关联前已经保存的上下文副本。

关联和删除共用 memory clock 仲裁。若先确认回声，后续删除把回声来源纳入目标闭包；若先删除原来源再确认回声，登记关联的同一事务根据已撤销的父请求，为本回声追加独立删除决策，并记录不含正文的审计和 outbox。原载荷 manifest、操作摘要和已经提交的删除目标均不改写。若平台 SENT 收据已存在，输入接纳事务内直接处理精确关联，避免晚到回声在提交后短暂成为可读副本。早于 SENT 的回声仍可作为未确认的平台输入进入上下文，随后只依据真实收据收敛；其他用户独立投稿的相同文字保留自身来源。

真实关联不因闭包超过读取预算而回滚。读取和新正文写入仍检查动态祖先，超过 4096 条来源时明确不可用；普通遗忘若目标闭包超限则整笔拒绝，不能返回成功。迟到的删除证明采用分批传播：每次根据已撤销的父请求抑制回声自身，撤销其所有平坦载荷副本；这些被撤销的请求头成为下一批传播依据。`PayloadStore.scrub` 每批先处理最多 `limit` 个待传播关联，`remaining` 同时计算待传播关联及未清理正文，只有两者都清空才表示本轮结束。旧库迁移按最多 256 个关联一批迭代到固定点。传播尚未到达的副本不能依赖其暂存的 ACTIVE 标记判断可读，必须经过动态来源检查；不得把单次 scrub 当作完整清理成功。

033 的不可清理回执字段不仅限制键名，还在数据库中限制标量类型、标识符长度、状态枚举和整数范围；人工裁定 result_metadata 同样采用封闭结构。嵌套正文、任意额外键和无效数值不能通过这些列落库。完整回执和裁定原因仍保存在可删除载荷中。

SQL 准备、固定版本的 Python 数据搬运、旧列清空及最终约束恢复在同一个迁移事务内完成。输入来源使用原 SourceEvent 身份登记，历史顺序明确标为 RECONSTRUCTED，资格来自实际已提交的 InputBatch。历史发送保留原请求字节及摘要，不进行重新序列化；无法证明完整依赖的旧派生载荷带有保守 legacy 来源标记。存在迁移前 suppression 时，未知 legacy 派生不得再次导入可读正文。

已删除或缺失正文的历史 Reply 不再复制成新的 SourceUnit，后台回填仍推进持久游标，避免每次重启卡在同一记录。

同一 Inbox event_id 的重复接收可返回已经存在的元数据收据。同一来源在另一个 Binding/Conversation 晚到、需要新增 occurrence 且该来源已经 suppression 时，使用独立的受控 metadata-only 输入接纳协议；它不复用仅供升级使用的 legacy importer，也不恢复旧明文列。详细线性化与收据边界见[已遗忘来源的迟到观察接纳](p5-suppressed-occurrence-ack.md)。

## 已验证边界

真实隔离 PostgreSQL 测试覆盖原 001–028 输入/图片/发送记录升级、原图及带签名 URI 的物理删除、排队/领取/许可/网络开始后的删除边界、UNKNOWN 人工裁定、操作与来源依赖幂等、原 owner 晚到回执，以及真实 Reply/Control 的来源继承。测试通过本地 TCP 服务核对实际原图下载和实际 OneBot HTTP 字节；不代表完成了真实 QQ 账户验收。

精确回声回归另覆盖：关联早于/晚于删除、已 SENT 后才收到回声、发现前的模型快照副本、两级回声依赖、读取超限回滚、真实 PostgreSQL 中超过 4096 条动态祖先时仍保留证明、迟到关联后的逐批删除传播、发布版本 001–022 的既有 alias 非空升级，以及重复升级不追加删除决策。容量测试使用人工构造的宿主来源引用，只验证存储边界，不代表语义或用户授权验收。元数据专项直接通过 SQL 尝试写入嵌套正文，验证数据库拒绝，而合法平台回执及完整受管正文继续可读。
