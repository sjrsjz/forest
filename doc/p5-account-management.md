# P5 Web 账号与固定角色管理

## 1. 当前实现范围

本切片把首次初始化后只有一个管理员的临时状态扩展为可日常使用的 Web 账号生命周期。部署账号仍只存在于部署数据库，不会成为 Bot、群聊用户或产品 Agent。当前提供两个固定角色模板：

| 角色 | 部署 HTTP | 目标 Bot 票据 | 账号管理 |
|---|---|---|---|
| `admin` | 读取与写入 | 可签发当前动作白名单内的读写票据 | 列表、创建、预览和提交 |
| `viewer` | 只读 | 只签发 `READ_ACTIONS` 中的用途限定票据 | 不可读取账号目录或提交新变更 |

查看者可以观察部署配置、Bot 目录、组件配置与运行元数据，不能靠直接调用 HTTP 绕过页面限制。`WebAuthority` 在部署事务中读取账号当前角色，只给查看者签发读取 action；目标 Bot 仍独立核验签名、action、Bot、输入摘要、policy revision 和三十秒期限。页面隐藏写按钮只是交互提示，服务端和目标库才是授权边界。

当前模板还没有 Bot 级 scope、独立运维角色、审计内容读取授权、平台身份映射或 MFA。它们仍属于完整 P5 权限模型，不能把当前 `viewer` 称为完整审计角色。

## 2. 账号身份与会话

`web_accounts.id` 是不可复用的主体身份；用户名只用于登录。账号不物理删除，因为配置、包、Bot 目录和审计事实可能引用主体。退役账号使用 `disabled=true`，恢复仍沿用原账号 ID 和递增 revision。

账号列表只返回 ID、用户名、固定角色、停用状态、revision、创建时间和当前未撤销且未到期的会话数量。密码 verifier、会话 token 摘要、CSRF 摘要、签名密钥与密码幂等摘要均不返回。

角色、停用状态或密码提交后，目标账号的全部会话在同一事务撤销。角色升级因此必须重新登录，旧查看者会话不会在原页面中突然取得写权限。修改自己的密码或角色后响应要求重新认证；自我停用被拒绝，必须由另一名管理员执行，以免提交成功但响应丢失后再也无法查询结果。

## 3. 创建账号

`POST /management/v1/accounts` 接收目标用户名、初始密码、角色、操作者当前密码和稳定 `Idempotency-Key`。入口在有限并发的工作线程中验证操作者密码并生成随机盐 scrypt verifier，数据库事务随后再次检查：

1. 取得部署级账号 advisory transaction lock；
2. 锁定当前操作者账号并验证它仍启用、仍是管理员且密码 verifier 未变化；
3. 锁定并验证当前 Web 会话仍有效；
4. 按 `(subject_id, idempotency_key)` 查找不可变请求；
5. 同输入重试返回原结果，不同输入返回 `IDEMPOTENCY_CONFLICT`；
6. 创建稳定账号 ID，写入账号、不可变请求、审计和 outbox 后提交。

密码本身和无密钥散列均不进入幂等账本。`WebAuthority` 初始化一把独立随机的加密 HMAC 密钥，对用途和密码生成服务端不可离线猜测的 `password_secret_digest`；这把密钥不复用 Ed25519 签名种子。随机盐 verifier 可以每次重新生成，幂等比较仍保持稳定。

## 4. 账号变更计划

已有账号通过两个阶段修改：

- `POST /accounts/{account_id}/change-plans` 冻结目标角色、停用状态、加密的新密码 verifier、操作者/目标 revision、计划摘要和十分钟期限；响应只含差异、`password_change` 布尔值与计划引用。
- `POST /accounts/{account_id}/management-requests` 携带计划 ID/digest、目标 expected revision、操作者当前密码与稳定幂等键，执行最终提交。

提交事务的锁序为：部署账号 advisory lock → 操作者账号 → 操作者会话 → 不可变请求 → 计划 → 目标账号 → 计划时钟复核 → 目标会话。全局账号锁同时串行化管理员集合变化和用户名创建，避免两个并发降级都根据过期计数移除最后管理员。

最终提交复核以下条件：

- 操作者密码 verifier、角色、会话与计划中的操作者 revision 仍有效；
- 计划未过期，目标、摘要和 expected revision 完全一致；
- 目标 revision 未改变；
- 若本次会移除一个有效管理员，提交后仍至少存在一个启用管理员；
- 计划实际改变角色、停用状态或密码。

成功后目标 revision 加一，账号、会话撤销、不可变管理请求、`audit_records` 和 `outbox_events` 原子提交。多个页面不会最后写入覆盖；输家收到当前 revision 或最后管理员错误并重新预览。

## 5. 响应丢失与权限收紧

同一已提交请求在计划过期后仍可按原幂等键恢复。自我降级会撤销旧会话；操作者可用原凭据以查看者重新登录，再提交同一计划引用和幂等键。入口允许已认证查看者到达账号提交恢复端点，存储层只在找到属于该主体且语义摘要一致的既有请求时返回原结果；任何新操作仍要求事务当前看到管理员角色。因此恢复通道不能让查看者应用新计划。

自我改密后使用新密码重新登录可采用同一路径。账号被另一管理员停用后不能自行恢复响应，但其他管理员仍可从审计及账号状态核对；完整操作日志查询页将在后续切片提供。

## 6. 验证边界

真实 PostgreSQL/ASGI 测试覆盖创建幂等与输入冲突、重名、查看者部署与 Bot 目录读取、部署写入和账号目录拒绝、查看者注销、停用撤销会话、审计/outbox 原子记录和密码不回显、最后管理员保护、两个管理员并发自我降级，以及降级者重新登录后恢复原回执。目标授权测试还验证查看者的 `config.read` 票据能被 Bot 接受，而 `config.plan` 在签发端被拒绝。

真实 Edge 专项覆盖账号创建、选择、变更预览、密码不进入预览、应用后刷新、晚到列表响应隔离和移动端无横向溢出。最终 Docker 镜像还通过独立 Compose 项目的完整浏览器流程：真实初始化后创建查看者，在隔离会话登录并读取部署状态，页面隐藏写入口，直接向写 API 发请求仍由服务端返回 `PERMISSION_DENIED`；随后继续验证既有双 Bot、Agent、记忆、热重载与重启恢复。没有验证外部身份提供商、MFA、Bot 级授权或真实反向代理部署。
