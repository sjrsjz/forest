# 模块运行时架构

本文记录已讨论的架构方向。当前工作区实现了序列化库、令牌路径工具、内存 ACL 查询、SQLite 配置存储及独立 OneBot API 库，下述运行时、插件 SDK 与包工具尚未实现。具体 ABI 和未定行为不在本文中默认选定。

## 1. 目标与职责

Forest 采用 Rust 宿主与 Wasm 模块。宿主提供模块执行、生命周期、通信及受控资源访问；具体功能由模块实现，Agent 是其中一个模块。

调度器管理的是模块及其调用，位于底层异步执行器之上：

| 层次 | 职责 |
|---|---|
| 底层执行器 | 推进异步任务、等待 I/O、使用执行线程 |
| 模块调度器 | 创建实例、派发请求、关联返回结果、协调实例替换 |
| 模块 | 实现接口，解释自身配置和状态，决定何时向其他模块发送消息或发起调用 |

调度器不解释具体模块的数据字段，不要求模块把状态转换写成数据库函数，不引入跨模块共享数据库事务作为普通调用的基础。

## 2. 包、实例与线程

- **插件包**：不可变的代码、类型契约和静态资源。
- **模块实例**：某个包的一次运行实体，拥有自身配置、状态表和执行资源。
- **线程**：执行载体，不是包或实例的身份。

同一包可以创建多个实例。替换一个实例，不意味着替换全部同包实例。包身份、某次构建的工件身份和运行实例身份分别表达。

Wasm 实例有线性内存等运行状态，但它们不会自动跨实例销毁、重建而保留。可恢复状态由宿主状态表承载，见[状态与访问详细设计](02-state-access-and-reload.md)。

线程池分配、实例是否固定线程、单实例是否允许重入，均尚未决定。

## 3. 插件包组成

包携带以下内容；下面只说明逻辑组成，文件名及分发格式尚未固定：

```text
plugin/
├── manifest.toml
├── module.wasm
├── interfaces/       # 由类型与接口声明生成
├── assets/           # 可选静态资源
└── ui/               # 可选管理界面
```

manifest 描述包身份、包版本、运行 ABI 与入口。接口描述表达模块提供的接口、需要调用的接口，以及参数、返回值、错误、配置和状态项的类型。

配置声明还包含各项允许读取、写入的主体规则。插件声明谁可以访问自己的配置，宿主装载并执行，不以插件申请自身配置访问权替代资源声明。规则属于插件元数据，普通配置写入不能改变，详见[配置访问声明](06-config-access.md)。

Rust 类型是类型契约的来源，复用 Forest 的 `Schema`、`Value` 与 derive。不要要求开发者再手工维护一份与类型声明重复的 JSON Schema 或字段转换程序。

用户配置、可恢复状态和实际运行数据位于包外。替换包不覆盖这些数据。builtin 与外部插件采用同一包与生命周期模型，builtin 仅表示随框架发行。

包版本、运行 ABI 版本与数据格式版本是不同概念，不通过其中一个推断另一个。具体版本编码及兼容性声明方式待定。

## 4. 接口与生命周期

Wasm 可以导出多个函数。单入口是调用约定的选择，不是 Wasm 的限制。模块的概念接口包括：

| 部分 | 职责 |
|---|---|
| `create` | 根据配置和宿主保留的状态建立运行对象 |
| 对外开放的接口 | 处理消息或请求，返回声明的结果 |
| 宿主通信入口 | 由模块主动请求发送消息、调用其他模块 |
| `destroy` | 释放实例资源 |

这些名称说明职责，不是已固定的导出符号或 Rust trait。

配置与可恢复状态留在宿主表中，`snapshot` 不作为所有模块必须实现的标准钩子。重载不复制旧 Wasm 的线性内存、对象地址或执行栈。

候选实例的初始化与开始对外工作需要区分。如何触发主动工作、创建任务与打开连接，需结合任务模型继续确定；当前不预先扩展一组生命周期钩子。`destroy` 不承担隐式保存必要状态的职责。

## 5. `send` 与 `call`

| 操作 | 返回的含义 |
|---|---|
| `send` | 调度器已接受消息，或提交被拒绝；不表示接收方已处理完成 |
| `call` | 等待接口结果，或取得调用过程中的框架错误 |

`send` 的返回值为提交操作的 `Result`。接收方后续处理错误不通过已经返回的 `send` 传回；需要执行结果时使用 `call`。

被调用模块返回 `Result<T, E>`，其中 `E` 是模块声明的错误。调用方看到的结果还包括框架错误，类型关系如下：

```rust
enum CallError<E> {
    Module(E),
    Framework(FrameworkError),
}

type CallResult<T, E> = Result<T, CallError<E>>;
```

这段代码仅表达类型关系，尚未作为 SDK 实现。框架错误和模块错误保留来源及结构，显示文本不决定错误含义。Wasm trap 等执行失败归框架处理，不伪装成模块主动返回的错误。

框架报错不自动证明模块未执行或没有产生修改。当前不引入自动重试及自动超时行为。

## 6. 通信边界

模块间通信统一经过调度器。传递的数据使用类型化契约与序列化值，不交换另一模块的 Rust 对象、引用或内部客户端。

实际操作来源由调度器从执行上下文确定，不由消息正文、接口参数或模块自行声明。调用保留发起者，执行模块身份由宿主实例信息确定；内部表访问与代用户执行的管理操作分别按其授权对象处理，见[令牌设计](03-token.md)。

正常接口调用与数据访问各自在其宿主边界处理类型和权限约束，不要求每个模块重复解释字符串协议。

## 7. 待定项

- 插件归档格式、生成接口描述的存放形式、底层 Wasm ABI，以及是否使用 Component Model。
- 逻辑接口的命名、查找、依赖绑定及替换时的兼容性规则。
- 单实例的并发与重入语义，嵌套调用和队列顺序。
- 主动任务如何受实例生命周期管理，以及长任务是否需要显式安全点。
- `call` 的异步等待和取消语义；尚未设计超时机制。
- 调用上下文的具体类型及宿主授权入口；配置项 ACL 的声明语义见[配置访问声明](06-config-access.md)，来源保留与执行模块的区分见[令牌设计](03-token.md)。
