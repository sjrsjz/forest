# 模块运行时架构

本文记录已讨论的架构方向。当前工作区实现了序列化库、令牌路径工具、内存 ACL 查询、SQLite 配置存储及独立 OneBot API 库，下述运行时、插件 SDK 与包工具尚未实现。具体 ABI 和未定行为不在本文中默认选定。

## 1. 目标与职责

Forest 采用 Rust 宿主与 Wasm 模块。宿主提供模块执行、生命周期、通信及受控资源访问；具体功能由模块实现，Agent 是其中一个模块。

当前范围为单个 Bot 账号，可同时处理多个群聊。不设计多 Bot 实体目录、账号选择路由或跨账号配置挂载；群聊仍可由接收模块独立排队并异步处理。

调度器管理的是模块及其调用，位于底层异步执行器之上：

| 层次 | 职责 |
|---|---|
| 底层执行器 | 推进异步任务、等待 I/O、使用执行线程 |
| 模块调度器 | 创建实例、派发请求、关联返回结果、协调实例替换 |
| 模块 | 实现接口，解释自身配置和状态，决定何时向其他模块发送消息或发起调用 |

调度器不解释具体模块的数据字段，不要求模块把状态转换写成数据库函数，不引入跨模块共享数据库事务作为普通调用的基础。

## 2. 包、单例对象与执行资源

- **插件包**：不可变的代码、类型契约和静态资源。
- **模块对象**：由 Manifest 的 `package.id` 声明的单例逻辑模块，拥有稳定 Token 及所属配置和状态表。
- **Wasm 执行实例**：实现逻辑模块的执行资源，热重载时可替换，不单独取得对象身份。
- **线程**：执行载体，不是模块身份。

一个已登记对象正常运行时只有一个活动实现，不引入同包多实例、部署实例名或独立实例 Token。热重载的旧/候选执行实例仅参与同一对象的内部交接，不能作为两个独立模块对外服务。

Wasm 实例有线性内存等运行状态，但它们不会自动跨实例销毁、重建而保留。可恢复状态由宿主状态表承载，见[状态与访问详细设计](02-state-access-and-reload.md)。

单例模块可以有多个未完成调用，但同一执行实例一次只推进一个任务。时间片被动让出保留实例执行权，任务主动结束本次推进才释放；接口用 reentrant 区分是否允许多个未完成调用，详见[调度设计](09-scheduling.md)。线程池分配和执行资源是否固定线程仍未决定。

具体实现以[调度器状态机](12-scheduler-state-machine.md)收敛：六个模块阶段、Idle/Advancing 两种实例执行权，以及随请求移动的接口许可、接纳额度和一次性返回出口。就绪、被动暂停和完成不各自再维护可变副本，宿主资源终结后才允许下一实例初始化。

## 3. 插件包组成

包包含外部 Manifest 和 Wasm 工件。文件格式及字段见[模块 Manifest 详细设计](07-module-manifest.md)，包归档和分发方式尚未固定：

```text
plugin/
├── manifest.json    # 包身份、工件位置、配置与 ACL、接口契约、宿主事件接收声明
└── module.wasm      # 实际包内位置由 Manifest 指定
```

Manifest 顶层为 `package`、`module`、`configs`、`provides`、`uses`、`subscriptions`。接口契约、宿主事件接收声明、配置 Schema、默认值和 ACL 对宿主外部可见，不依赖执行描述导出函数才能取得。生命周期入口和逻辑方法到 Wasm 入口的映射由统一 ABI 规定，Manifest 不逐包配置这些名字。当前不引入 ABI 版本字段，也不包含 UI 配置。

配置声明还包含各项允许读取、写入的主体规则。插件声明谁可以访问自己的配置，宿主装载并执行，不以插件申请自身配置访问权替代资源声明。规则属于插件元数据，普通配置写入不能改变，详见[配置访问声明](06-config-access.md)。

类型契约复用 Forest 的 `Schema`、`Value`。Manifest 先确定外部表示，不重造一份 JSON Schema；Rust 声明与自动生成工具的接入另行设计，本阶段不要求双份手工契约。

用户配置、可恢复状态和实际运行数据位于包外。替换包不覆盖这些数据。builtin 与外部插件采用同一包与生命周期模型，builtin 仅表示随框架发行。

上线前按同一套正在开发的模块契约推进，宿主、SDK 和插件随契约变更同步更新，旧开发包重新构建。不预设 ABI 版本协商、多版本兼容或迁移分支。包版本仅用于识别发布工件，不据此推断接口兼容性；公开稳定后的兼容策略届时另行确定。

## 4. 接口与生命周期

Wasm 可以导出多个函数。单入口是调用约定的选择，不是 Wasm 的限制。模块的概念接口包括：

| 部分 | 职责 |
|---|---|
| `create` | 根据配置和宿主保留的状态建立运行对象 |
| 对外开放的接口 | 处理消息或请求，返回声明的结果 |
| 宿主通信入口 | 由模块主动请求发送消息、调用其他模块 |
| `destroy` | 释放实例资源 |

这些名称说明职责，不是已固定的导出符号或 Rust trait。

配置与可恢复状态留在宿主表中，`snapshot` 不作为所有模块必须实现的标准钩子。重载不复制旧 Wasm 的线性内存、对象地址或执行栈。

create 负责初始化，禁止 send/call（包括宿主原生服务对象），成功后才开放普通入口；正常退出运行受限 destroy，trap 或 Force 不执行来宾清理，宿主按实例资源所有权回收。外部卸载/重载有 Drain、AtYield、Force 三种方式，详见[生命周期设计](10-module-lifecycle.md)。必要状态由模块显式保存，不承诺强制退出时仍有机会写回；不另增一组初始化和停止钩子。

## 5. `send` 与 `call`

| 操作 | 返回的含义 |
|---|---|
| `send` | 调度器已接受消息，或提交被拒绝；不表示接收方已处理完成 |
| `call` | 等待接口结果，或取得调用过程中的框架错误 |

`send` 的返回值为提交操作的 `Result`。接收方后续处理错误不通过已经返回的 `send` 传回；需要执行结果时使用 `call`。

宿主的外层 Result 只表达派发与执行是否正常完成。被调用模块返回的 `Result<T, E>` 是接口数据的一部分，调度器传递它而不解释 E。类型关系如下：

```rust
type DispatchResult<R> = Result<R, DispatchError>;
type CallResult<T, E> = DispatchResult<Result<T, E>>;
```

这段代码仅表达类型关系，尚未作为 SDK 实现。`Ok(Err(e))` 表示成功取得模块错误，外层 Err 才表示宿主派发或执行失败。宿主可以校验结果符合接口 Schema，但不依据 E 的内容选择重试、降级或其他操作。Wasm trap 等执行失败归宿主处理，不伪装成模块主动返回的错误。DispatchError 已明确包含 `QueueFull`，其他具体变体继续设计。

`DispatchError::QueueFull` 表示目标模块的接纳容量不足，**本次请求未被接受，目标没有执行本次请求**。send 和 call 都在提交阶段返回该错误；已接受请求的排队、主动等待和恢复不重新申请接纳容量，不在之后被改判为 QueueFull。容量核算见[调度设计](09-scheduling.md)。

时间片让出和异步等待保留原调用，不以 DispatchError 结束它。send 的 DispatchResult 只反映提交阶段，不能将接收方后续失败塞回已经完成的提交返回值。

ABI 实现须区分模块可见的错误数据与 Wasmtime 的执行控制错误：Wasmtime 宿主函数直接返回 Rust Err 会终止当前 Wasm 执行。可处理的 DispatchError 应编码进正常 ABI 返回数据，完成编码后对 Wasmtime 返回正常结果，不能将这两层 Result 混用。依据见 [Wasmtime 宿主函数错误语义](https://docs.rs/wasmtime/latest/wasmtime/struct.Func.html#method.new)。

框架报错不自动证明模块未执行或没有产生修改。当前不引入自动重试及自动超时行为。

上句是一般边界；QueueFull 已明确限定为接纳前拒绝，具有“目标未执行本次请求”的保证。框架仍不自动重试该请求，由提交方决定后续操作。

## 6. 通信边界

模块间通信统一经过调度器。传递的数据使用类型化契约与序列化值，不交换另一模块的 Rust 对象、引用或内部客户端。

实际操作来源由调度器从执行上下文确定，不由消息正文、接口参数或模块自行声明。调用保留发起者，执行模块身份由宿主实例信息确定；内部表访问与代用户执行的管理操作分别按其授权对象处理，见[令牌设计](03-token.md)。

正常接口调用与数据访问各自在其宿主边界处理类型和权限约束。提供方在接口声明上挂静态 AccessPolicy，send/call 统一检查 callers；配置读写分别检查 readers/writers，三种许可互不隐含。复用同一套 ACL 查询与主体模式匹配，不建立动态授权系统，见[访问声明](06-config-access.md)。

普通调用仅按 `(对象 Token, 接口路径)` 寻址。接口路径可为任意合法具体 Token，包括根路径，不限制固定前缀，也不再增加接口下的方法名这一层。接口路径在所属对象内唯一，跨对象可重复。`uses` 直接声明目标对象与接口路径，不引入依赖槽位，详见[Manifest 设计](07-module-manifest.md)。

热重载对其他包保持对象身份、地址和调用契约；调用者不持有目标的 Wasm 函数或执行实例，无需替换后重新绑定。Drain 完成旧请求，显式 AtYield/Force 可以中断旧调用，框架不自动重试。宿主保持结果关联与交接期间待派发请求，候选破坏已发布接口契约时不能直接透明切换。

群消息等事件由宿主接入能力产生，调度器内置 notifier 按模块 Manifest 的静态接收声明投递为普通请求，不直接重入处理器。模块没有事件生产声明或发布宿主接口，彼此通信仍使用 send/call。宿主处理逐目标接纳结果，接收宿主事件不产生同名插件加载依赖，详见[notifier 与依赖设计](11-notifier-and-dependencies.md)。

## 7. 待定项

模块需要的通信、单项配置、HTTP、WebSocket、受管文件、日志和时间接口见[宿主接口设计](08-host-interfaces.md)。该文档确定职责与最小操作，不表示底层 ABI 或异步执行模型已实现。

- 插件归档格式、自动生成方式、底层 Wasm ABI，以及是否使用 Component Model；外部声明形式已见[Manifest 设计](07-module-manifest.md)。
- 两端地址的内部路由、在途调用与热重载交接的协调；单例身份和接口路径语义已在 Manifest 中确定，不引入依赖槽位。
- 单例模块的执行权、两种让出、接口重入限制和基本队列顺序已见[调度设计](09-scheduling.md)；嵌套等待的死锁处理本阶段不设计。
- 主动任务如何开始，以及静态依赖环的装载规则；create 已禁止 send/call，长期任务的卸载选择已见[生命周期设计](10-module-lifecycle.md)。
- `call` 的异步等待和取消语义；尚未设计超时机制。
- 调用上下文的具体类型及宿主授权入口；配置和接口的静态 ACL 语义见[访问声明](06-config-access.md)，来源保留与执行模块的区分见[令牌设计](03-token.md)。
