# P4 图文索引、召回与 Agent 接入

本文记录已实现的运行链路。每个 Bot 使用自己的数据库；群来源在同一 Bot 记忆域中形成不同主干，查询结果保留群与作者。配置与限制见 [记忆配置](p4-memory-config.md)，图发布协议见 [持久图存储](p4-graph-store.md)。

## 数据进入记忆

全部群消息先进入持久 Inbox。只有已被实际 InputBatch 接纳的消息才能参与索引和召回；静默排空同样产生资格，不需要 Agent 回复。自己发送的回声、取消的任务触发、不可读记录、不完整的派生来源和已遗忘来源被排除。

`MemoryRuntime` 独立于 Agent 模型配置。文本按连续 UTF-8 片段生成独立 facet，保留原始字符跨度；图片根据允许的来源捕获原始字节，使用持久媒体身份，直接发给图文嵌入模型。不同作者即使发送相同文字，也有不同来源身份。运行过程不会生成图片说明或裁剪摘要，不调用 LLM 压缩记忆。

图片下载有数据库并发许可、每次大小、每日流量及总存储预留。首次捕获成功的原图固定，下载失败不会创建伪造的空文本向量。查询可定向建立当前图片的捕获记录，无需等待后台扫描遍历全 Bot。下载和嵌入均在事务外执行，发布时重新检查来源、配置、Host、维护与删除版本。

## 异步写与发布

| 数据 | 并发处理方式 |
|---|---|
| 来源、facet、图贡献 | 稳定身份去重；相同文字的不同来源不合并身份 |
| 图断言、关联与撤回 | 归约稳定事实；乱序与重复写可合流，冲突保留为并列证据 |
| 图视图 | 短事务 CAS 固定来源和本分片修订，再分配 Bot 全局图修订；重启和无变化刷新不重复发布 |
| 嵌入请求 | 固定原始 HTTP 字节、配置、来源、空间和请求身份；一个 facet 的文档向量只发布一次 |
| 调用预算与并发 | Bot 运行时锁下统一接纳；前台查询与后台索引共用 `PREPARED`/`DISPATCHING` 槽，不靠进程内计数保证上限 |
| 查询结果和 Agent 绑定 | 一次性决策；后来的索引结果不能替换已经固定的 EvidenceBundle |

确定未发送的嵌入请求可以有限重试原字节。`UNKNOWN` 保留成本预留，不自动重发。已知响应即使因配置或删除版本变化失去发布资格，仍记录真实费用；不会为了维持预算数字而抹去已发生的费用。每日 token 配额是接纳时的预留门槛，供应商返回的实际用量超过预留时仍如实计费，因此它不是供应商账单的绝对硬上限。

## 图文查询与证据固定

Agent 在当前模型步骤的不可变快照中选取最后一个实际触发记录作为查询来源。该记录的原生文本、图片分别形成查询 facet；不能从最新 Inbox 额外取尚未进入切口的消息。查询身份绑定 Bot、Run、输入修订、输入切口、来源及记忆配置。在工具完成后，如果输入切口未改变，下一次模型调用复用同一查询与证据，避免重复调用嵌入 API。

当前向量检索使用 PostgreSQL 同一嵌入空间的精确点积。每个查询 facet 最多选择 64 个候选，再对独立候选源执行 RRF 排序；文本与图片查询不通过平均向量互相抵消。扫描不持有 Host 或群聊事务锁。最终短事务重新检查每个候选的来源资格、当前会话可见性、固定切口和删除版本，再冻结有界结果。

来源资格筛选只读取元数据，不预先解析原始正文；缺失正文的来源和依赖在该资格查询的 `LIMIT` 前排除。向量 Top-K 仍先生成有界候选，后续授权可能减少候选，空结果不保证召回完整。通过权限与结果预算筛选后才加载实际证据内容，避免高消息量下先读取大量候选正文再丢弃。

每条证据包含原始 `source_unit_id`、群来源、平台/realm/身份 schema、作者、有序文本和图片、匹配 facet。证据正文在可清理的 PayloadStore 中，依赖原始查询、返回来源、图像捕获及向量结果。晚到索引不能改变该正文；已撤销证据不能通过再次检索同一 query ID 恢复。

图片缺失、配额耗尽、嵌入结果未知或搜索超时产生明确降级；空结果不证明不存在相关记忆。准备、下载、嵌入、搜索和绑定共用前台查询期限。超时后只保留一个短元数据提交窗口；无法提交则进入恢复，不能把未落库的决定当成已完成。关闭运行时会取消并回收自身扫描、捕获、查询、嵌入任务及 HTTP 客户端。

## 模型投影与执行权限

规范上下文保持不变。EvidenceBundle 作为来源明确的历史数据投影到模型请求，包含当前群与来源群的关系；它不产生新用户触发，也不授予工具权限。模型请求 manifest 固定证据身份、摘要、配置和切口，Agent 存储检查它与本步骤持久绑定一致。

模型只支持文本时，投影移除图片像素，保留缺失原因及来源标记。原始图片、索引和召回仍然存在。视觉模型使用有来源归属检查的真实捕获字节。请求预算优先保留原本可保留的规范上下文，额外证据按排名整条丢弃，不为召回继续牺牲历史。连空降级标记都无法容纳时明确报告输入预算不足。

模型发送许可、工具接纳及 Kernel 实际工具写事务、工具组关闭、上下文发布和最终回复重新验证本 Run 使用过的证据。遗忘发生在模型 HTTP 之后时，已知用量仍结算，返回的正文和工具提案不再写入或执行。遗忘发生在工具许可之后但 Kernel 尚未接纳调用时，记录确定未发送并结束运行；已接纳的效果遵守原有回执和 UNKNOWN 对账协议。

## 已验证与仍需完成

实际验证使用 PostgreSQL、原生 Worker、本地 TCP 图片/嵌入/LLM/OneBot 服务，覆盖跨群原图、图片与混合查询、两轮模型复用、同群排队切口、文本/视觉投影、迟到删除与费用、配置切换、全局并发及关闭恢复。对应测试见 [查询](../tests/test_memory_queries.py)、[运行时](../tests/test_memory_index_runtime.py)、[Agent 集成](../tests/test_agent_memory_runtime.py)、[撤权](../tests/test_agent_memory.py)和[投影](../tests/test_memory_projection.py)。浏览器与完整平台回归结果以[实现状态](implementation-status.md)的完成记录为准。

目前 WebUI 提供嵌入/媒体/查询预算和运行状态。自由输入文字或上传图片检索、图浏览器、人工关联管理尚未接入页面。图存储支持跨主干关联贡献，但 Agent 检索目前使用原始来源的向量证据；跨分片的全局关联扩展与冲突解释仍需接通。精确向量扫描有期限与候选上限，尚未提供 ANN 索引或大规模容量验收。

新记忆载荷已经支持来源撤销与派生正文清理；旧 Inbox、Agent、工具、上下文、发送和审计等正文副本还需要完成[统一载荷迁移](p4-payload-migration-notes.md)。因此当前不宣称已实现全聊天历史的物理遗忘。真实 QQ、商业模型、嵌入语义质量和供应商实际计费仍需配置真实服务后联调。
