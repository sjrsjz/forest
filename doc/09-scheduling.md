# 模块任务、执行权与重入调度

本文明确模块的调度语义：同一 Wasm 执行实例一次只推进一个任务；时间片被动让出保留实例执行权，模块主动让出释放执行权；接口只区分可重入与不可重入，不引入数值并发上限。

本文规定调度语义，运行时及基础 SDK 已实现，见[运行与 ABI](13-runtime-and-sdk.md)。死锁检测、死锁规避、普通 call 的取消接口、超时、优先级和抢占式任务迁移不属于本次范围。外部卸载/重载引发的中断按[生命周期设计](10-module-lifecycle.md)处理。模块与接口寻址沿用[Manifest 设计](07-module-manifest.md)，宿主功能沿用[宿主接口设计](08-host-interfaces.md)。

具体状态、所有权转移和交错情况的审查见[调度器状态机](12-scheduler-state-machine.md)。本文说明调度语义；不应将描述性的“运行中”“被动暂停”“已完成”各自再存成一份可变状态。

## 1. 调度单位

| 概念 | 定义 |
|---|---|
| 模块对象 | Manifest 声明的稳定单例身份，对外按对象 Token 寻址 |
| 执行实例 | 对象当前使用的 Wasm 内存、全局状态和执行资源 |
| 调用任务 | 一次已开始、尚未结束的接口处理，具有独立输入、上下文、结果关联和可恢复进度 |
| 一次推进 | 从模块任务开始或恢复执行，到其主动让出、完成或执行失败为止 |
| 实例执行权 | 独占推进某个执行实例及操作其来宾内存的权利 |

同一实例中的不同接口和任务可以访问同一份模块内存。多个未完成任务不等于多个线程同时执行 Wasm；这里不引入 Wasm 线程或多个执行实例共享线性内存。

一个执行实例最多有一个执行权持有者。一次推进可以消耗多个时间片，但在它结束前，其他任务不能进入该实例。不同模块实例可以由不同执行线程并行推进，也可以在同一线程轮转，规则不依赖固定线程归属。

## 2. 两种让出

### 2.1 时间片被动让出

调度器通过运行时的可恢复让出机制暂停正在执行的 Wasm。它可以发生在模块的一次状态修改尚未结束时，模块不需要提前整理数据或声明安全点。

被动让出时：

1. 当前调用、Wasm 执行栈、实例执行权和接口占用全部保留。
2. 执行线程可以转去推进其他实例。
3. 同一实例的其他任务、接口入口和 ABI 辅助入口不能进入；宿主不能趁暂停任意读写其来宾内存。
4. 该实例再次获得运行机会时，继续被暂停的同一次推进，不重新调用任务入口。

时间片耗尽不是任务完成、主动让出或错误，不释放任何重入限制，也不使实例具备热重载交接条件。运行时应选择 yield/resume 行为，不以 trap 实现普通时间片切换。

### 2.2 模块主动让出

模块任务通过 SDK 的异步机制结束本次推进，明确返回“任务尚未完成，等待后续推进”。这一边界才表示主动让出。

主动让出时：

1. SDK 已将该任务的后续进度保存在实例内部，当前推进入口已正常返回。
2. 实例执行权释放；同一实例可以推进其他就绪任务或开始允许的新调用。
3. 原调用仍未完成，其来源、结果关联和接口占用保留。
4. 等待条件满足时，原任务重新进入就绪队列，而不是立即回调 Wasm。

模块作者必须保证主动让出时，共享状态允许其他任务访问，不保留与这种访问冲突的借用。跨让出点需要维持的关系，由模块自行组织数据和协调；宿主不检查数据含义，也不自动回滚、合并或加锁。

**调用宿主函数本身不等于主动让出。** 日志、已经完成的 I/O 查询或其他立即返回操作可以发生在一次推进中，不释放执行权。即使宿主内部临时等待，也不能仅凭其 Rust Future 返回 Pending 就认定模块已交出执行权。

## 3. 模块任务与运行时 Future 的边界

使用模块任务的可恢复表示，SDK 可用 Rust Future 保存进度。宿主每次进入 Wasm 只要求 SDK 推进指定任务一次，而不是为每个完整异步处理器保留一个独立的 Wasmtime 调用栈。

概念上的推进结果为：

```rust
enum Step {
    Pending,
    Ready(Value), // 完整接口输出，包含模块自己的 Result<T, E>
}
```

此处定义结果语义；ABI 草案以 create/invoke/destroy 建立任务，以 poll 统一推进，具体字节编码另行固定。新任务创建、推进和必要的 SDK 收尾都受同一实例执行权保护。状态机将其包成 OwnedAdvance，在参数与结果缓冲区收尾完成之前不释放执行权。

必须区分两层 Pending：

| 观察位置 | 含义 | 执行权 |
|---|---|---|
| 宿主驱动本次 Wasmtime 调用，其 Future 返回 Pending | 本次推进尚未返回，包括时间片暂停或运行时内部等待 | 保留给原任务 |
| 本次 Wasmtime 调用正常完成，SDK 返回 Step::Pending | 模块任务明确结束本次推进，等待后续运行 | 释放 |
| 本次 Wasmtime 调用正常完成，SDK 返回 Step::Ready | 模块任务完成 | 输出取回及 ABI 收尾后释放 |
| Wasmtime 返回 trap 或其他执行失败 | 本次推进异常终止 | 按实例失败处理，不假定状态仍可继续使用 |

被动暂停期间，宿主只继续驱动原来的运行时 Future，不再对同一个 Store 发起第二个独立调用。模块主动让出之后，上一轮 Wasmtime 调用已经结束，下一次推进才重新进入实例。

这种方式与“普通 core Wasm 同步导入函数在宿主异步等待期间，其来宾栈始终挂起”的执行方式不同。后者不能仅因等待就复用 Store 来推进另一个独立调用。依据见 [Wasmtime 异步执行机制](https://docs.rs/wasmtime/latest/wasmtime/#asynchronous-wasm)和[调用 Future 的存活约束](https://docs.wasmtime.dev/c-api/async_8h.html)。

## 4. 宿主 I/O 与唤醒

SDK 向模块提供可 await 的 HTTP、配置、文件、WebSocket、模块 call 等操作。底层提交操作、保存结果和通知任务的具体 ABI 后续确定；其调度语义为：

1. 模块显式发起操作，宿主记录所属任务和可信调用上下文。
2. 操作若已完成，SDK 可以直接返回结果，任务继续执行，不发生主动让出。
3. 操作尚未完成时，SDK 登记唤醒关系。模块任务只有真正结束本次推进并返回 Pending，才交出执行权。
4. 操作完成后，结果先留在宿主，任务标记为就绪。I/O 完成回调不直接调用模块、不修改来宾内存，也不绕过执行权。
5. 任务获得下一次推进机会后，SDK 取回结果并继续原处理。

宿主 I/O 不通过阻塞当前执行线程实现。时间片只约束可恢复的 Wasm 执行，不保证能中断任意原生宿主函数；原生操作必须按异步提交和完成通知推进。

登记等待与检查完成状态必须保证不丢失唤醒：若通知在任务仍处于推进或被动暂停期间到达，要保留通知；当本次推进返回 Pending 时，已有通知使任务直接回到就绪队列。重复通知可以合并，但不能产生同一任务的多个同时推进。

唤醒只表示可以再次检查进度，不表示任务已经完成。任务可以再次返回 Pending，或在同一轮连续完成多个立即就绪的 await。

SDK 不得为多个任务制造指向同一模块对象的冲突可变引用，也不能让返回 Pending 的任务继续持有一个供其他处理器重复借用的整体 `&mut Module`。可重入处理器的共享状态访问应采用适合任务交错的借用范围；这属于 SDK 类型约束与模块实现责任，不由调度器反射检查。

## 5. 接口重入限制

每个普通提供接口在 Manifest 中明确声明：

```rust
reentrant: bool
```

本设计中的“重入”指接口能否同时存在多个未完成调用，包括来自独立请求和同一调用链的调用，不仅指调用栈递归。不另行区分调用来源来绕过限制。

| 声明 | 新调用的开始条件 |
|---|---|
| false | 该接口没有未完成调用 |
| true | 不因该接口已有未完成调用而阻止新调用 |

没有 N 或 `*` 数值字段；true 表示接口不设置固定在途数量上限，不承诺无限资源。两种接口都受同一实例的独占推进规则约束。

不可重入接口的占用从调用开始时建立，直到调用完成并收回输出后释放。时间片暂停、宿主 I/O 等待、模块主动让出以及等待再次获得执行权，都不释放该占用。尚未开始的排队请求不占用接口。

限制属于准确的 `(对象 Token, 接口路径)`，不是所有同名接口的全局锁，也不是整个模块的锁。A 接口不可重入且正在等待时，B 接口仍可开始；两者若访问共同状态，模块仍须保证主动让出边界正确。

true 也不意味着正在执行时可以嵌套调用另一个入口：新任务只能在实例没有执行权持有者时开始。模块 call 经过队列；宿主函数不偷偷直接回调本实例的另一个处理器。

恢复一个已经开始的任务不属于新调用，不能因它自己占用了不可重入接口而阻止恢复。模块正常返回 Err 仍属于调用完成，可以释放占用；trap 不作为正常完成后立即继续派发其他任务，见第 9 节。

## 6. 就绪、排队与执行选择

目标模块设置有限的总接纳容量，覆盖已接受的排队请求和全部未完成调用，包括 Waiting 任务；容量约束既考虑数量，也考虑已接纳输入的数据大小，不只限制物理队列长度。数值与配置位置后续在运行时资源配置中确定，不增加接口的数值重入字段。

接纳时，容量检查、预留额度和请求入队作为同一次不可分割的宿主状态操作。容量不足就返回 `DispatchError::QueueFull`，不入队、不开始任务、不改变已有请求；不得先报告接受成功，再因队列满撤销。框架不自动等待额度、重试、丢弃或合并消息，也不在队列外无限保存待接纳请求。

额度属于稳定模块对象，普通派发、主动让出、时间片暂停和唤醒恢复都不重新申请或释放。调用完成、输出取回及相关任务数据清理后释放；异常退出则在宿主清理对应请求与任务时释放，不能在资源仍保留时提前视为空闲。热重载保留已有额度核算，新请求在交接期间仍须接纳；不能通过替换执行实例或暂停派发绕过容量上限。接纳额度不承诺限制模块执行中自行分配的全部内存。

QueueFull 仅表示新提交未被接受，不表示模块正在等待就一定拒绝，也不阻止已经接受的任务恢复和完成。true 接口同样受模块总接纳容量约束。这是资源接纳限制，与接口能否重入分别判定。

调度器按所有权区分请求和任务：

- 未开始的 AcceptedRequest 位于接口 FIFO 或交接队列，携带输入、可信上下文、接纳额度和返回出口。
- 开始请求时取得接口许可并建立 StartedTask；当前任务移入 OwnedAdvance，实例驱动权只有 Idle/Advancing 两种形态。
- SDK 返回 Pending 且 ABI 收尾完成后，任务移入挂起表。就绪与等待由去重就绪队列中的通知投影，不另存 ready 布尔值。
- 完成时消费任务、返回出口及许可，不在调度表保留可再次执行的 Finished 行。诊断记录不参与调度。

时间片被动暂停仍是同一个 OwnedAdvance，不增加独立 Preempted 状态。尚未开始的请求没有来宾 Future，只有轮到请求且实例空闲时才建立任务。

开始推进时消费已有就绪通知，推进期间的新通知保留；返回 Pending 后不再清空通知。若已有通知，任务可以再次被选择，否则等待。具体原子边界和迟到通知的归属见[状态机的唤醒规则](12-scheduler-state-machine.md#6-唤醒没有先睡着再检查的窗口)。

实例每次获得运行机会时按以下顺序处理：

1. 若已有 OwnedAdvance，只在其 runtime Future 就绪时恢复它；不选择其他任务。
2. 否则，从该实例的就绪工作中按就绪顺序选取一个任务或允许开始的请求。
3. 请求开始前检查目标接口占用；不可开始的请求继续排队，不能阻挡其他接口或已有任务的恢复。
4. 开始请求时移入唯一接口许可、建立任务及绑定上下文，随后独占推进。
5. 被动暂停保留原推进；主动 Pending 在 ABI 收尾后移交任务；完成时收回输出、消费返回出口并归还许可。

同一接口的待开始请求按接受顺序开始。已就绪任务和可开始请求按就绪顺序轮转，不固定优待新请求或恢复任务；被占用接口的队首请求变为可开始时，再加入可选工作。请求是否可开始只在宿主调度状态中判定，不探测来宾数据。

实例之间按就绪队列轮转；一个实例因时间片被动让出后回到实例就绪队列，但其内部持有者不变。一次推进主动让出或完成后，若该实例还有可运行任务或可开始请求，也放回实例就绪队列尾部。队列中的实例记录去重，不能因多个任务就绪就让同一实例被多个执行线程同时选中。具体时间片参数属于运行时配置，不进入模块接口契约。

若运行时 Future 因实际等待而返回 Pending，则依赖其唤醒通知重新调度，不忙轮询；这仍是原推进的挂起，执行权不释放。不能把所有运行时 Pending 都当成时间片耗尽并立即重排。

如果某个任务始终计算且从不主动让出，它会持续占用本实例，但时间片机制允许其他实例运行。不在此时插入本实例其他任务来追求公平，因为那会破坏本方案承诺的执行边界。

## 7. 示例

假设接口 A 的 reentrant 为 false，接口 B 为 true，两者属于同一实例：

| 时刻 | 事件 | 实例执行权 | A 的占用 |
|---|---|---|---|
| 1 | A1 开始修改状态 | A1 | 保留 |
| 2 | A1 时间片耗尽；A2、B1 到达 | 仍归 A1，A2/B1 排队 | 保留 |
| 3 | 运行其他模块后恢复 A1 | A1 | 保留 |
| 4 | A1 等待 HTTP，主动返回 Pending | 释放 | 保留 |
| 5 | B1 可以开始，A2 仍不能开始 | B1 | 保留 |
| 6 | HTTP 完成，A1 就绪 | 不抢占当前持有者，也不直接回调 | 保留 |
| 7 | B1 结束本次推进，轮到 A1 恢复并完成 | A1，随后释放 | 完成后释放 |
| 8 | A2 可以开始 | A2 | 由 A2 占用 |

若 A 的 reentrant 为 true，A2 在第 4 步后也可参与调度；它仍不能在第 2 步插入 A1 的未结束推进。

## 8. 保证与责任

本方案保证在没有 Wasm 共享线程、没有宿主越权访问来宾内存的前提下，一次推进不会与本实例另一任务交错。不同推进之间的共享状态可以变化；这不是完整调用的数据库事务或失败回滚保证。

模块作者负责主动让出边界、跨边界的状态关系以及不同接口对共同数据的访问。不可重入只控制某个接口的新调用，不替代数据结构约束，也不为一整段 get/await/set 自动提供原子性。

宿主配置接口仍是独立、原子的单项 get/set/reset。即使来宾保留执行权，其他模块或获准用户也可能修改同一配置项；实例执行权不是宿主数据表的全局锁。

调度器保留每个任务的可信来源和调用关联。推进任务时恢复对应上下文；主动让出、I/O 通知、时间片暂停均不重建身份，不把任务来源提升为宿主。

## 9. 生命周期和错误边界

create、destroy 是宿主控制的生命周期任务，不属于普通接口，不声明 reentrant。初始化完成前不向该实例派发普通调用。生命周期任务自身被动暂停仍保留执行权，主动等待也不能据此开放尚未完成初始化或正在销毁的实例。

create 与 destroy 均禁止 send/call，包括自身、其他模块和宿主原生服务对象；检查发生在请求接纳前，不将禁止的请求延后到普通工作阶段发送。生命周期限制独立于接口 access.callers，匹配 ACL 也不能绕过。

卸载/重载由外部选择 Drain、AtYield 或 Force，具体入口关闭、队列和调用结算见[生命周期设计](10-module-lifecycle.md)。Drain 完成旧集合中全部请求，包括尚未开始的队列请求；不能在排空时禁止这些请求开始。交接期间新接纳请求留给下一实例，不继续扩大旧集合。

停止来宾执行之后进入宿主 Releasing 阶段。当前实例直接持有的不可中断本地操作必须真正结束，才能创建下一实例；丢弃等待结果不等于 SQLite 工作线程已取消写入。此阶段不执行任何来宾导出，详见[状态机](12-scheduler-state-machine.md#22-releasing-不能省略)。

Waiting 任务仍是未完成调用，Drain 必须等待它结束。AtYield 则允许在执行权空闲的主动边界停止恢复其余旧任务，并在受限阶段运行析构与 destroy。若仍持有被动暂停的推进，须先恢复到主动返回边界。Force 可以在该边界前中断执行，跳过全部来宾清理。

长期接收任务可使 Drain 永久等待；这不触发自动超时或升级。AtYield/Force 是外部明确选择的结束方式，不迁移 Future、调用栈或连接。destroy 禁止 send/call 和新建连接，允许配置访问及基础清理。

模块返回自身 Err 是正常接口输出。普通执行 trap 后，未返回的 call 以执行失败结算，模块不可调度并由宿主回收资源，不再运行 destroy；只有外部热重载或卸载改变该故障状态。不能仅清空占用后继续运行其他任务，也不自动回滚、重放或重试。

本文不检测或消除嵌套调用的等待环，也不因同一调用链而绕过接口限制。死锁处理按本次范围明确留后，不据此扩展协议。
