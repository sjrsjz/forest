# 模块生命周期与组重载

生命周期使用 RAII 风格：create 建立实例内部状态与资源，正常退出运行 destroy，宿主最终回收实例拥有的资源。不迁移 Wasm 内存、Future、调用栈或连接。执行边界见[模块调度](09-scheduling.md)，数学模型见[形式化模型](34-scheduler-formal-model.md)。

## 1. 对象、实例与管理请求

对象 Token 是稳定的寻址身份；Wasm 实例是一次具体执行。模块间 uses 可以形成有向环，装载通过声明闭包联合校验，不要求拓扑排序。

装载、重载和卸载以一个对象集合为目标，由宿主管理请求持有。请求与模块阶段分开：

```text
Preparing → Waiting → Committed → Succeeded / Failed
Preparing / Waiting → Cancelled
```

同一对象同时只属于一个管理请求。互不重叠的请求可以并行准备；提交时重新校验目标实例与整个预期目录。已提交请求的候选契约参与其他管理操作的依赖检查，防止在候选尚未发布时卸掉它需要的提供者。

候选读取、摘要检查、编译和兼容性检查都先于旧实例停止。默认 Drain 等待期间，所有旧实例仍为 Serving，普通 call、send 和 notifier 正常接纳。没有提前关闭入口，也没有等待期间的下一实例队列。

## 2. 自然静止与原子提交

对目标集合 S，Drain 要求所有当前实例在同一个控制边界上同时静止：

- 没有取得过执行权但尚未完成的任务，包括已经主动让出、正在等待 call 或 I/O 的任务。
- 没有仍持有实例执行权的推进。
- 没有尚未终结的任务收尾工作。

尚未取得执行权的 Object 请求（普通 call/send 与模块事件）只持有宿主数据，没有来宾 Future、栈或状态修改，不阻止重载。提交时把它们移入交接队列，由新实例首次执行；保留输入、来源、返回通道、接纳额度和同接口 FIFO 顺序。它们不是已开始任务的恢复或重放。

实现使用既有接纳凭据判断这些条件：从已占用的请求数和输入字节数中扣除 FIFO 中未启动请求持有的份额，余量必须全部归零。不另建第二套在途任务计数。驱动器先结束 ABI 与本地操作收尾，再释放相应凭据。

对象仍被其他 Manifest 引用、配置仍保存在数据库、实例仍持有闲置连接，都不等于存在未完成调用。

静止判断、兼容性复核、转移未启动队列和整组入口关闭在同一目录锁中完成。取得首次执行权的 START 与重载提交由此排序：START 先发生，该任务必须结束；重载先提交，该请求由新实例执行。候选准备完毕后，驱动器在领取请求前先检查整组是否可提交，避免在每个任务结束后又不断启动旧队列。

Instance 请求（激活、I/O 通知）绑定旧实例，即使未开始也必须完成；它们不从接纳预算中扣除。激活使用独立控制接纳名额，同样必须归还。空闲原生监听没有接纳凭据，不阻止提交。

Object 请求只完成接纳不阻止提交。提交前排队请求先移入交接队列，提交后新请求追加其后。不得检查为空后释放控制权，再按过期结论执行销毁。

持续繁忙可能使请求一直 Waiting。管理员可以取消等待或明确选择 Force；运行时没有默认等待期限，也不把等待时间解释为模块故障。

## 3. 取消与强制选择

Preparing / Waiting 请求可以通过宿主管理入口取消。取消撤销管理意图，旧实例继续服务；因为 Pending 没有关闭入口，所以无需恢复队列、重放请求或回滚普通工作。

取消与提交由同一控制边界排序。提交先发生，则取消明确返回“已提交”；进入 destroy、Force 中断或旧资源释放之后，不存在恢复旧实例的取消分支。管理调用的等待者退出也不等于撤销请求，必须使用明确的取消接口。

对 Pending 请求选择 Force，会把整组请求改为 Force，仍须通过候选与兼容性检查。对 Committed 请求选择 Force，则中断组内当前仍在执行、停止或初始化的实例；不可中断的本地原子操作仍须终结。

## 4. 三种停止方式

| 模式 | 提交前的条件 | 提交后的处理 |
| --- | --- | --- |
| Drain | 整组自然静止，旧入口一直正常服务 | 对空闲旧实例运行 destroy |
| AtYield | 候选通过检查，管理员明确选择有损停止 | 关闭整组入口，等当前完整推进交回，中断其他旧工作，再 destroy |
| Force | 候选通过检查，管理员明确授权中断 | 关闭整组入口，中断旧工作，跳过 destroy |

AtYield 不把时间片被动暂停当成安全边界。当前 OwnedAdvance 包括输入分配、invoke/poll、输出读取和 ABI 收尾。它交回之前不能插入 destroy；没有推进时可以直接开始受限清理。

Force 使用运行时中断机制，不强杀操作系统线程。Force/trap 后不运行来宾 destroy、free 或其他清理导出。旧任务的 call 按中断或失败结算；send 已返回的接纳结果不能追回，后续中断写入诊断。

显式 AtYield / Force 可以中断普通请求；Drain 不主动中断旧普通工作。三种方式都不回滚已经发生的远端副作用，不递归取消已接纳到其他模块的请求。

## 5. 整组替换与发布

```text
联合检查候选
→ 等待整组自然静止（Drain，可取消）
→ 原子提交、关闭整组旧入口
→ 销毁并回收全部旧实例
→ 创建全部候选实例
→ 全部成功后原子发布整组声明、ACL 与入口
```

实际运行 create/destroy 或等待资源回收时不持有目录锁。原子性覆盖提交与发布，不覆盖整个异步生命周期。

旧实例全部释放后，逻辑对象进入 Staged：它持有稳定地址、接纳预算和可能的交接队列，但没有可执行实例。只有全部旧成员完成回收，才安装整组配置声明，之后再开始候选 create。所有声明默认值须在任何 create 运行前存在，避免环内初始化读取同组配置时遇到声明竞态。

某个候选先初始化成功时，仍停留在 Creating，并等待组发布许可。没有部分成员提前 Serving 的状态。成功发布后，驱动器获得许可，继续处理其交接队列。

Drain reload 的交接队列先接收旧 FIFO 中尚未启动的请求，再接收提交后的新请求。它们仍按旧的公开契约和 ACL 接纳，保留原接纳决定和同一份额度，不因转移再次调用或重新鉴权；候选兼容性保证新实现接受这些输入并满足原输出契约。整组发布时统一切换对外声明和 notifier 关系。新订阅不补发历史事件，不对新旧实例重复投递。

一个候选 create 失败，整组不发布。成功创建但尚未发布的成员运行受限 destroy；尚在初始化的成员在完成后清理，管理员仍可显式 Force。所有候选回收后进入 Failed，交接请求按相应调度错误结算。旧实例已经销毁，不宣称初始化失败自动回滚旧实现，也不回滚持久写入。

已经提交的替换可以在旧实例停止或清理发生 trap 后继续候选；这与普通 trap 后自动重启不同。没有管理替换计划的普通 trap 只使故障模块进入 Failed，回收其资源，不级联卸载其他模块。

## 6. 生命周期能力

create / destroy 都禁止 send/call/emit，以及 ws_watch/timer_after，包括对自身和宿主原生对象。初始化不通过调用其他模块建立等待，循环依赖因此不需要生命周期拓扑顺序。

create / destroy 同样禁止 lock/unlock。普通任务使用的锁表属于具体 Wasm 实例，仅协调该实例内的任务；正常停止先结束任务和原生收尾，trap/Force 则停止整实例并回收锁表，不向其他实例交接锁或传播毒化状态。

| 宿主操作 | create | destroy |
| --- | --- | --- |
| 配置 get / set / reset | 按 ACL | 按 ACL |
| 模块私有 SQLite、受管文件 | 允许 | 允许，等待本地原子操作终结 |
| HTTP、WebSocket 连接与收发 | 允许 | 禁止 |
| WebSocket 主动关闭 | 允许 | 允许 |
| 日志、当前时间 | 允许 | 允许 |
| sleep | 允许 | 禁止 |
| send / call | 禁止 | 禁止 |

执行实例访问自己的配置时，使用该实例随包绑定的 ACL；外部访问使用对象已经发布的 ACL。清理未发布候选也不能误用旧实现的自身权限。

create 未完成而被 Force 或 trap 结束，只由宿主回收，不析构半初始化对象。destroy 失败仍完成宿主回收，生命周期错误保留模块声明的 Schema、Value 和阶段，不变成普通接口错误字符串。

## 7. 卸载、故障与资源

卸载集合 S 需要满足：提交后的目录中，不存在组外模块继续依赖 S 的接口。循环依赖可以整组卸载；单独卸掉仍有使用者的成员会拒绝。全局关闭按整个已装载集合处理，不再逆拓扑逐包卸载。

Drain 卸载没有下一实例接收请求，因此仍等待全部已接纳请求执行并收尾，不能套用重载时保留未启动队列的条件。AtYield / Force 保持显式有损停止的语义。

Releasing 等待已提交且不可中断的本地文件或数据库操作结束。丢弃等待 Future 不代表工作线程中的写入不会再提交。旧本地操作终结后才允许新 create，避免旧写入追上新实例。

连接、操作句柄、任务及缓存属于具体执行实例。已结束任务的迟到结果不按 Token 交给下一实例；关闭旧接收出口不等于撤销远端修改。

配置键集合与 Schema 必须保持兼容；允许更新默认值并保留全部当前值。组入口统一发布不构成跨多次调用或跨数据库的全局事务。状态规则见[配置表](05-config-table.md)及[状态交接](02-state-access-and-reload.md)。

## 8. 发布后激活

module.activated 可选，指向 Unit 输入普通接口，callers 允许 /system/lifecycle。整组成功发布时，在交接请求前提交一次绑定新实例的激活，使用独立一个控制名额。等待期间其他处理器可执行；Serving 表示已发布，不表示外部连接已经成功。激活返回模块错误按普通 send 记录，trap 停止整实例。无需额外 before_destroy：正常 destroy 与宿主资源回收已经承担收尾。

正常停止和故障处理均先终结能够注册监听的宿主操作，再取消并 join 原生监听，最后释放实例。旧通知不能进入新实例。
