# 模块生命周期与三种卸载方式

本文明确正常卸载、热重载及 trap 后的处理。采用 RAII 风格：create 建立实例内部状态并取得资源，正常退出运行 destroy，宿主最终释放属于该执行实例的资源。不迁移 Wasm 内存、Future、调用栈或连接，不引入卸载超时或自动升级卸载方式。

本文是设计，运行时尚未实现。调度与主动让出的精确定义见[调度设计](09-scheduling.md)，调用结果与接纳错误见[运行时架构](01-module-runtime.md)。

阶段转换收敛为 Creating、Serving、Stopping、Destroying、Releasing、Failed，具体载荷、入口规则及所有权证明见[调度器状态机](12-scheduler-state-machine.md)。重载是停止后的明确去向，不另叠加 reloading 布尔值。

## 1. 身份、资源与静态注册

逻辑模块的 Token 和已保存配置独立于 Wasm 执行实例。连接、等待操作、实例内任务及缓存属于具体执行实例；模块可主动释放，实例销毁或失败时由宿主回收其名下资源，不为下一实例维持连接。

notifier 的事件及其 Schema 由宿主定义，模块 Manifest 只声明宿主事件的接收入口。宿主装载声明建立静态注册表，不提供模块发布、运行中订阅或取消订阅接口。卸载、失败与热重载直接改变对象是否可调度；移除旧接收声明或替换注册表属于宿主生命周期操作，不要求模块先调用取消订阅。

注册关系保存稳定对象和接口地址，不保存 Wasm 函数指针。候选接收声明在正式切换前不覆盖当前声明，交接期间不向新旧实例重复投递。接收接口的 access.callers 静态声明允许哪些可信主体调用，宿主事件投递也执行这一检查，见[notifier 设计](11-notifier-and-dependencies.md)。

从明确启用的模块集合出发，按 uses 的模块依赖图确定加载闭包、启动顺序和卸载影响范围；宿主事件需求单独检查对应能力支持，不把事件源解释成插件生产者。依赖分析不自动安装包，也不根据某段消息内容猜测要加载哪个模块。依赖环的接纳规则另行确定，不在本轮引入运行时死锁处理。

## 2. create 与普通工作

create 负责建立本实例正常工作需要的内部对象，可以通过宿主基础接口读取已有配置。只有初始化成功，宿主才开放该实例的普通入口和 Manifest 事件投递。

create 不是一个以“永远等待接收消息”为主体的常驻调用；初始化必须完成，之后的普通任务按调度规则推进。模块可以在初始化中取得连接等资源，资源立即登记到候选实例名下，初始化失败同样需要宿主回收。

**create 禁止 send/call，包括对自身、其他模块和宿主原生服务对象的调用。** 即使目标已就绪或 callers 允许也不能绕过。宿主在接纳前按生命周期阶段拒绝，不缓存成“初始化成功后自动发送”的请求。初始化只能使用允许的基础宿主接口，包括配置、受管文件、直接网络操作、日志与时间；异步等待不开放普通入口。

这一限制保持模块间的初始化边界，不表示 create 是可回滚事务。配置写入和直接网络操作仍可能产生已经提交的外部修改，初始化失败不撤销它们。

普通工作阶段允许模块按契约使用 send/call、配置、网络和受管文件接口。事件由 notifier 提交为普通请求，受 QueueFull、实例执行权和接口 reentrant 限制；网络结果就绪仍只是唤醒，不绕过调度直接进入模块。

不增加 prepare/start/commit 等初始化钩子。静态依赖分析负责加载范围及普通入口的开放，不以允许 create 跨模块调用来解决启动问题；主动任务的启动方式与依赖环的装载规则仍另行确定。

未完成的 create 可以由外部 Force 结束，随后只做宿主回收；不对半初始化对象调用 destroy。Drain/AtYield 用于已经完成初始化的普通工作，不隐含新增“初始化失败后仍可正常析构”的契约。

## 3. 关闭旧实例入口

外部发起卸载或重载时，明确选定卸载方式，默认采用排空。宿主先关闭旧实例的新请求入口，并在这一时点确定旧实例已经接纳、尚未结算的请求集合。普通 call、send 与 notifier 投递使用同一入口状态。

热重载保留逻辑对象。切换期间新到请求可以留在宿主有界队列中等待新实例，不进入旧请求集合，也不延长旧实例的排空；容量不足仍返回 QueueFull。这里阻止的是新消息进入旧实例，不增加无限等待队列。

真正卸载不再为该对象接纳新请求；依赖该对象的模块是否一起卸载，由管理操作结合静态依赖图决定，不自行把它们改接到另一个对象。

关闭入口不撤销已提交的宿主操作，不等于关闭所有连接，也不是模块已经销毁。之后按以下三种方式处理旧请求。

## 4. 三种卸载方式

| 方式 | 普通任务的停止条件 | 未结算旧请求 | 是否运行 destroy |
|---|---|---|---|
| 排空 Drain | 旧实例已接纳请求全部处理完成 | 继续执行并正常结算 | 是 |
| 主动让出 AtYield | 实例当前推进入口正常返回，执行权空闲 | 中断其余旧请求 | 是，使用受限宿主操作 |
| 强制 Force | 中断运行中的 Wasm，不等待主动让出 | 中断其余旧请求 | 否，不再执行任何来宾清理代码 |

卸载方式由外部管理操作选择，不由普通模块消息自行提升。等待太久不自动从 Drain 切换到其他方式，不设置自动超时。

### 4.1 排空

旧集合中已经排队但尚未开始的请求也继续执行，不能把“暂停接收新请求”误写成“不再处理已有队列”。正在等待宿主 I/O 的任务继续等待并恢复；接口 reentrant 限制和执行权规则不变。

旧请求全部结束、输出取回并清理任务数据后，进入 destroy。此方式保证不因卸载主动中断旧请求，不保证模块自己的处理必然成功，也不保证永不结束的任务最终结束。

因此，包含永久接收任务的模块可以使 Drain 一直等待。这是显式选择排空的结果，不另外发明停止钩子或偷偷关闭连接。需要结束这种模块时，由外部明确选择其他卸载方式，或者模块自身正常结束任务。

### 4.2 主动让出

只在没有普通任务持有实例执行权时进入清理。若 OwnedAdvance 仍存活，继续原推进，直到它正常返回 Pending 或完整结果并完成 ABI 收尾；不能在时间片暂停点直接运行 destroy，也不能在 poll 与输出释放之间插入清理。

若旧实例已经处于所有任务均 Waiting/Ready、没有推进存活的状态，可以立即采用这个边界，不要求每个等待任务再主动让出一次。当前推进若先返回完整结果，该请求正常结算；尚未结算的其他旧请求不再恢复或开始。

宿主中断剩余旧请求，并让 SDK 的任务析构与 destroy 都在同一个受限清理阶段执行。只释放任务的保存状态，不重新 poll 被中断的 Future，也不执行其 await 之后的普通处理代码。

进入来宾清理前，宿主在 Stopping 内终结这些任务直接持有的本地操作：解除可取消的本地等待，等待不可中断的原子写入结束，避免旧写入覆盖 destroy 保存的状态。这不恢复旧任务，也不等待远端撤销或下游模块完成；连接等仍由之后的 destroy 和宿主回收按所有权释放。

此边界保证不会插入一次尚未结束的状态修改，但不保证整个异步调用已经完成。因此旧请求已经产生的配置或外部修改可以保留，未完成的整体操作也可能只完成一部分；框架不回滚、不补偿、不重放。

旧任务此前已经投递给其他模块的请求不因本实例卸载而自动撤销；对应结果随后到达时，只清理失效关联，不再恢复旧任务，也不交给新实例冒充其等待结果。

### 4.3 强制

正在执行的 Wasm 由运行时中断并以 trap 结束。这里的强制不表示在任意机器指令处杀死操作系统线程；必须使用运行时支持的中断机制，停止实际执行后才能销毁实例。

如果实例已经没有正在执行的 Wasm，直接废弃保存的任务与实例资源，不为触发一个形式上的 trap 而重新进入模块。

不运行 destroy，也不调用 SDK 析构入口、来宾内存释放函数或其他清理导出。模块内部状态可能处于任意中间阶段，宿主不得假定调用某个辅助入口就是安全的。连接等资源由宿主自己的资源所有权回收。

原生宿主操作不能通过强杀执行线程终止。已经提交的配置操作仍须维持原子提交或回滚语义，已经发送到对端的操作也不能因 trap 被视为撤销；结束等待与回收结果关联不构成副作用回滚。

## 5. destroy 的宿主操作白名单

destroy 与正常处理器使用同一身份和配置 ACL，没有额外管理员权限。宿主根据当前清理阶段执行白名单，不能仅由 SDK 不导出某个方法来限制。

| 操作 | destroy 中是否允许 |
|---|---|
| 配置 get/set/reset | 允许，仍执行 ACL、Schema 和单次原子操作 |
| 日志、读取当前时间 | 允许 |
| 释放已有资源、关闭已有连接 | 允许 |
| 受管文件读写与删除 | 允许，范围仍限于模块数据目录 |
| send/call，包括宿主原生服务对象 | 禁止 |
| 投递消息或创建新的普通任务 | 禁止 |
| 新 HTTP 请求、新建网络连接或监听 | 禁止 |
| WebSocket 发送或接收应用消息 | 禁止 |
| sleep 或注册后续定时工作 | 禁止 |

关闭已有资源可以执行必要的底层协议关闭，但不能借关闭入口提交应用消息或产生新的模块请求。配置存储和资源回收是宿主基础操作，不经由调用其他模块来绕过限制。

基础异步操作若需要等待，destroy 可以按正常任务推进机制挂起和恢复；实例仍处于清理阶段，不因此重新开放普通入口。此期间的阶段限制始终保持。destroy 没有自动超时，外部仍可明确改用 Force。

destroy 或任务析构发生 trap 时，立即按异常退出处理，不再次调用 destroy，不尝试运行剩余来宾清理代码。宿主继续回收自己的资源。

## 6. 请求结算与故障

Drain 中旧请求按普通完成规则结算。AtYield 和 Force 中没有完成的旧 call，包括旧集合中尚未开始的 call，均返回框架中断异常；不会伪装成模块主动返回的 Err。错误变体的完整编码随 DispatchError 定义确定，不把这次中断误报为 QueueFull。

已经返回成功的 send 只确认接纳，不能追加返回异常。非排空方式可能中断或弃置未完成的旧 send；宿主记录这次中断，不把它自动迁移为新实例的普通处理，也不向发送者伪造完成回执。正常排空没有这种主动弃置。

热重载期间在旧入口关闭之后新接纳的请求属于下一实例，不因旧实例的计划卸载被当成旧任务中断，也不重复接纳或重复扣容量。它们只有在新实例可调度后才开始执行。

普通执行发生 trap 时，尚未返回的 call 都按执行失败结算，旧执行实例标记为不可调度；新 call/send/notifier 投递直接拒绝，不再向故障模块积压消息。send 的已返回提交结果不能追回。跳过 destroy，宿主回收资源；只有外部热重载或卸载可以改变该故障状态，不自动恢复。

执行结果与管理请求由调度控制边界排序。已结算结果不撤回；Force 被接受时仍未结算的旧请求按中断处理，之后即使 runtime 返回也不执行来宾结果释放。AtYield 则允许当前完整推进正常完成后再中断其他旧任务。每个 call 的一次性返回出口随请求所有权移动，不另设多处可竞争的完成回调。

## 7. 热重载顺序与保证

基本顺序为：

1. 读取、校验并编译候选包，确认对象 Token 和接口契约满足替换要求；此阶段不执行候选 create。
2. 关闭旧入口，按外部选择的 Drain、AtYield 或 Force 结束旧实例。
3. 正常方式完成受限 destroy；强制或 trap 跳过来宾清理。进入 Releasing，释放旧实例资源，并等待其直接持有的不可中断本地操作结束，不把连接交给候选。
4. 新实例读取保留配置并运行 create。
5. 初始化成功后，切换活动实现及 Manifest 注册关系，向新实例派发保留的新请求。

新 create 失败时，候选资源由宿主释放，对象保持不可调度并结算无法继续的调用，等待外部处理；不自动重新启用已经销毁的旧实例。create/destroy 已经成功提交的配置写入保留，不宣称 RAII 能回滚持久数据。

Releasing 与来宾停止分开：已经提交到 SQLite 工作线程的写入不能因等待 Future 被丢弃就视为取消。此阶段只运行宿主清理，不调用任何来宾导出；本地操作终结后才运行新 create。已接受的下游模块请求仍属于接收方，不通过回收原等待方去递归取消或排空它们。

外部已经批准重载时，旧实例在停止或清理过程中 trap，可跳过剩余来宾清理并在宿主回收后继续该候选。没有外部计划的普通 trap 最终进入 Failed；这两者不构成自动恢复策略。

所有方式保持逻辑对象地址，无需其他包重绑定。只有 Drain 具备“既有请求不因重载被主动中断”的保证；AtYield/Force 是外部显式选择的有损操作，不能再承诺调用者完全观察不到中断。未开始的下一实例请求不重放已经开始过的旧处理。

普通配置访问与声明更新仍分别遵守自身规则。外部 UI 写入和 Schema/default 变更的具体交接规则尚需确定，不因采用 RAII 就隐含加入跨模块事务、数据回滚或迁移机制。
