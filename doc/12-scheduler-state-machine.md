# 调度器状态机与所有权

本文规定当前调度器的控制状态和所有权边界。执行规则见[模块调度](09-scheduling.md)，生命周期见[模块生命周期](10-module-lifecycle.md)，推导与反例见[形式化模型](34-scheduler-formal-model.md)。

设计目标是由资源归属和状态转换保证正确行为。解析、Schema、ACL、容量和句柄校验留在外部边界，不让内部每一步重复猜测对象是否仍然有效。

## 1. 唯一控制边界

请求接纳、管理提交、实例状态转换和整组发布，由同一个目录锁排序。锁不跨 Wasm 执行、网络或本地工作线程等待。

驱动器独占 Store 与来宾推进 Future；宿主操作只持有自己的结果槽和任务唤醒关联。查询返回只读投影，不接纳请求、不初始化模块、不补配置默认值。

| 事实 | 权威持有者 |
| --- | --- |
| 当前模块阶段 | 对象目录中的 State 枚举 |
| 管理请求目标、提交状态及候选声明 | 管理请求记录 |
| 当前来宾推进及其任务 | 实例驱动器 |
| 未开始请求 | 接口 FIFO 或提交后的交接队列 |
| 逻辑互斥 | 等待操作完成槽或任务持有表中的唯一宿主锁许可 |
| 对象接纳额度 | 随请求、任务或收尾移动的 Admission |
| 可推进通知 | 去重的 Start / Resume 序列 |
| 普通 call 结算权 | 一次性返回出口 |
| 宿主操作结果 | 绑定具体实例和任务的完成槽 |

不增加独立的 accepting、reloading、ready 或在途任务计数来复述已有事实。

## 2. 管理请求与模块阶段分离

管理请求按目标对象集合保留身份。Preparing / Waiting 可以取消，Committed 不可撤回。请求的状态通过 watch 向管理者提供只读观测；完成或取消后不再占用目录中的管理请求位置。

```text
Preparing → Waiting → Committed → Succeeded / Failed
Preparing / Waiting → Cancelled
```

一个对象同时只能属于一个管理请求。互不重叠的请求可以准备不同候选，但其提交仍在目录边界重新检查当前实例和预期契约。

Pending 请求不修改 Serving，也不截断旧请求集合。默认 Drain 重载仅要求整组已开始任务及必要收尾全部结束，允许 FIFO 中仍有未启动请求。已占用额度减去 FIFO 持有额度即为尚未结束的工作，不需要从驱动器复制任务表或维护第二份 active 计数。Drain 卸载没有后继实例，仍要求全部接纳凭据归还。

候选兼容性检查在等待前执行，提交时再复核。已经 Committed 的候选契约参与其他管理操作的预期目录，防止候选尚未发布时其提供者被卸载。

取消 Pending 只撤销管理意图；没有旧入口或队列需要回滚。读取和编译的迟到完成不再有权提交。取消与提交按目录锁的顺序决定结果，不通过超时推测。

## 3. 模块状态

```rust
enum State {
    Creating { /* 候选实例与入口队列 */ },
    Serving(Live),
    Stopping { /* 旧实例、停止方式、后续动作 */ },
    Destroying { /* 受限清理实例、后续动作 */ },
    Releasing { /* 宿主资源终结、后续动作 */ },
    Staged { /* 没有实例的保留地址与入口队列 */ },
    Failed(InstanceFailure),
}
```

| 阶段 | 所有资源及普通入口 |
| --- | --- |
| Creating | create 尚在执行，或已经成功但等待整组发布；不运行普通任务 |
| Serving | 正常驱动器、FIFO 和任务；正常接纳 |
| Stopping | 已提交管理请求的旧实例；Drain 已静止，AtYield / Force 按选定规则结束 |
| Destroying | 仅受限来宾清理；不运行普通任务 |
| Releasing | 仅宿主清理；不运行任何来宾入口 |
| Staged | 旧实例已释放，保留稳定对象、预算与交接队列，等待整组后续步骤 |
| Failed | 没有可执行实例，保留失败数据，等待外部处理 |

没有装载表示目录中没有对象项。Staged 与 Releasing 不同：前者已经没有待释放实例，后者必须等待真实资源终结；两者不能用一个提前归零的标记混为一谈。

首次装载使用 Closed 入口；reload 提交后使用 Deferred 入口；卸载不接纳新请求。Ingress 是明确的枚举，不用多份布尔值决定路由。

## 4. 批量装载与发布屏障

从启用根集合按 uses 求可达闭包，记录已访问对象后可处理任意有向环。闭包列表仅使用确定性排列，不表示初始化拓扑顺序。宿主事件需求另行校验。

先在联合候选目录中检查目标、接口、Schema 和宿主事件权限；执行任何来宾 create 前，先安装整组配置声明。配置声明安装与实例资源挂载分开，避免同组成员互读默认值时发生注册竞态。之后再创建整组实例。create 不能 send/call，不存在依赖另一成员普通入口才能初始化的协议。

驱动器完成 create 和初始化操作收尾后，发送一次初始化结果，并等待发布许可。只有整组都已成功且未被中断，控制面才一次性将所有成员改为 Serving，切换声明、ACL 与 notifier 入口，再向各驱动器发送许可。

某成员失败时不给其他成员运行许可。已完成初始化的成员清理后释放；未完成初始化的成员仍可通过明确 Force 中断。全部资源回收后管理请求失败，不发布部分新实现。

## 5. 重载提交

默认 Drain 的提交步骤在一个目录临界区内完成：

1. 确认管理请求仍为 Pending，并且目标仍是准备时的实例。
2. 对重载，从各目标已占用请求与输入额度中扣除未启动 FIFO 持有的份额，确认余量均为零；卸载仍要求额度完全归还。
3. 复核联合候选目录和每个旧接口的输入逆变、输出协变及配置兼容性。
4. 将管理请求变为 Committed；Drain 重载把各接口尚未启动的 FIFO 移入交接队列，并关闭整组旧入口；卸载关闭入口而不保留队列。
5. 通知旧驱动器继续生命周期。

首次领取请求的 START 和提交使用同一目录锁。候选已经准备好时，驱动器在领取下一请求前先尝试提交，避免旧队列一直延后重载。移入交接队列的请求保留同接口 FIFO、原始来源、返回通道和接纳凭据；旧实例的 Start 通知不转给新实例，由新入口按队列重建。

提交前后新请求的归属由相同目录锁排序。Pending 期间回调仍进旧实例；提交时已经没有未完成旧任务需要依赖新来的回调。尚未启动的请求没有来宾状态，可以在新实例首次执行。

AtYield / Force 是显式的有损选择，不等待自然静止；提交授权驱动器按完整推进边界停止，或通过运行时中断结束。模式变化不会绕过类型检查。

所有旧成员释放后，整组进入 Staged，再开始整组候选 create。不会某个旧成员刚退出，就提前创建它的新实例。新成员也不在其他成员初始化前开放入口。

## 6. 实例执行权

```rust
enum Execution {
    Idle,
    Advancing(OwnedAdvance),
}
```

OwnedAdvance 覆盖输入分配与复制、invoke/poll、输出取回和 ABI 缓冲区收尾。Wasmtime Future 因时间片或内部等待返回 Pending，仍是同一个推进；只在该 Future 被唤醒后继续，不重入 Store，也不忙轮询。

SDK 返回 Pending 且整个 ABI 收尾结束后，才把执行权释放给其他任务。原 Future、调用上下文和已持有的宿主锁仍属于原任务。

开始一次推进时消费已有唤醒；期间到达的新通知保留。返回 Pending 时不再清空通知，因此不会丢失“在交权之前到达”的完成事件。

物理执行线程可以轮转到其他实例，但不让同一 Store 同时存在两个独立调用。来宾 free、alloc 等辅助入口也属于同一独占推进，不能趁其时间片暂停运行 destroy。

## 7. 接纳、任务与结算

接纳原子地检查阶段、uses、callers、Schema 与容量，预留 Admission，并将请求放入 FIFO 或交接队列。QueueFull 表示未接受、未执行，不在外面另建无限等待队列。

开始请求时，移出 FIFO、绑定任务和消费 Start 通知在同一控制边界完成；后续请求仍可在主动让出后开始。临界区使用显式 host lock，锁等待已经属于 Started，不再是未启动请求。恢复任务不重新申请接纳额度。

| 执行阶段 | 所有者 | Drain 重载 |
| --- | --- | --- |
| 待首次取得执行权 | 宿主 FIFO 中的 Request | 可交给新实例首次执行 |
| 已取得执行权、尚未完成 | 驱动器的 Started、来宾 Future 或必要收尾 | 等待其完成，不能迁移 |
| 已完成并收尾 | 结果已结算，凭据已归还 | 不再约束旧实例 |

START 是取得模块执行权并绑定实例的调度边界，不以是否已经执行第一条机器指令为判断依据。物理时间片尚未轮到、时间片暂停或等待下一次推进，不会把已绑定任务退回未启动状态。

普通结果只能消费一次性返回出口。模块返回 Err 也是正常输出；trap 不作为单请求错误后继续执行同一损坏实例。

异常退出可以先结算请求，再让回收对象持有 Admission 与已持有锁，直到其原生操作终结。额度释放通知在两种额度凭据实际归还之后发出，不能先通知静止、再归还资源。

send 只在接纳时确认；后续失败写入诊断。call 等待目标结算；关闭调用方等待出口不递归取消接收方，不迁移结果到新实例。

## 8. 停止、回收与失败

AtYield 只在完整 OwnedAdvance 交回后处理剩余任务；等待中的任务不需要再被 poll 一遍。中断任务的必要本地操作先结束，再执行受限 destroy，避免旧写入晚于最终保存。

Force / trap 终止整个实例的全部任务，不再调用来宾 destroy、free 或其他导出。先结算未完成任务，再等待不可中断的本地文件或数据库操作，最后释放资源。锁等待及尚未取走的授予在取消时释放；任务已持有的锁在该任务不可中断原生工作结束后释放。运行时中断不等于远端修改被撤销。

Releasing 完成后：普通故障进入 Failed；管理停止进入 Staged，由整组协调者决定卸载或创建候选。一个实例不得自行开始下一实例 create。

## 9. 配置与权限交接

执行实例访问自身配置使用自己包中绑定的 ACL，包含未发布候选的清理；外部访问使用目录中已发布的 ACL。候选未发布时不把其自身授权错误地套到旧实现上，也不提前向外部开放新权限。

相同键集合和等价 Schema 下允许更新默认值，保留全部当前值。增删配置或改换 Schema 仍拒绝兼容重载。配置 set、原子声明更新与整组入口发布不是跨数据库事务。

## 10. 不变量与范围

关键不变量为：同实例唯一推进、同实例同名宿主锁许可唯一、请求唯一归属、接纳有界、结果至多结算一次、宿主结果不跨实例误投，以及旧本地操作终结后才允许新 create。

状态安全不等于所有请求最终完成。持续繁忙时 Drain 可以一直 Waiting，管理员可以取消或显式选择 Force；不需要推断模块内部计算是否终止。静态环可以装载，普通调用等待环不由规划器自动解开。

当前没有 call trace、普通 call 自动取消、自动等待期限、自动恢复或已开始任务迁移。未启动请求可原样交接。可取消的是宿主管理请求的 Pending 阶段；Committed 以后只能继续既定交接或明确强制中断。
