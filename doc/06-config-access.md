# 配置与接口访问声明（ACL）

本文确认配置与接口的访问控制设计：**提供方在资源声明上挂静态 AccessPolicy，宿主绑定真实来源并执行声明。** 配置使用 readers/writers，接口使用 callers，均复用同一套内存 ACL 查询与主体匹配规则；不建立可动态编辑的 SQL ACL 表。

当前 `forest-util::acl` 已实现读、写、调用三种许可的内存表及只读 `check` 查询，`forest-config` 已实现 SQLite 数据存储。配置 Store 的 Declaration 不携带访问规则；Manifest 将规则编译为 ACL，宿主鉴权和 Wasm 入口已接入；现有原生 Store 不能直接作为未经鉴权的模块接口。

## 1. 规则属于目标配置

每个配置项的完整声明包含路径、Schema、必填默认值和访问规则。概念类型如下，实际 SDK 见[运行说明](13-runtime-and-sdk.md)；包内文本表示见[Manifest 设计](07-module-manifest.md)：

```rust
struct ConfigDeclaration {
    key: Token,
    schema: Schema,
    default: Value,
    access: AccessPolicy,
}

struct AccessPolicy {
    readers: Vec<SubjectPattern>,
    writers: Vec<SubjectPattern>,
    callers: Vec<SubjectPattern>,
}

enum SubjectPattern {
    SelfModule,
    Path(TokenPattern),
}
```

`SelfModule` 表示**拥有这份配置声明的单例逻辑模块**，由宿主绑定已登记的稳定对象 Token，即 Manifest 的 `package.id`。它不表示任意当前调用者，也不绑定某次 Wasm 执行实例。热重载的旧/候选执行实例属于同一对象，SelfModule 不因执行实现替换而改变。

`Path` 匹配宿主提供的真实主体路径，复用 `forest-util::token` 的完整路径匹配：`*` 为一段，`**` 为零到多段。模块可以构造同样的 Token 数据，但不能因此成为该主体。

插件声明仅对宿主确认为其所属的配置或接口生效。传入其他实体的 Token 不赋予声明所有权，也不能覆盖其他插件的访问规则。当前先挂载模块自身配置；用户等非模块实体的声明挂载按实际需求设计，不为多 Bot 预设配置层次，也不能依据目标路径的文本猜测所有权。

三个列表都显式提供。配置声明的 callers 为 []；接口声明的 readers/writers 为 []，callers 表达允许调用该接口的主体。它们不是把 send 当成写、call 当成读：send/call 都执行 Access::Call。

## 2. 判定语义

- 读取匹配 `readers`，写入匹配 `writers`，调用匹配 `callers`。命中相应列表中任意一项即满足该项 ACL；没有命中则拒绝。
- 先按准确的 `(实体 Token, 资源路径 Token)` 键对查表，不存在的键对一律返回 `false`。主体通配符不能授权不存在的资源，查询不补项或改变表。
- 空列表表示不向模块或用户开放该操作。声明必须明确提供访问规则，不自动补 `SelfModule` 或全体用户。
- 读、写、调用三种许可独立。写权限不隐含读权限，配置读写权不隐含接口调用权；调用权也不赋予配置访问权。
- 没有拒绝规则、规则优先级、父路径权限继承或“最具体规则优先”。通配符只负责主体匹配。
- 模块访问自己的配置也必须被声明允许。根路径 `/`、`/system/...` 或名为 admin 的身份均不自动绕过声明。

例如，一个内部状态项可以仅允许 `SelfModule` 读写；一个公开状态项可以允许 `/module/*` 读取、仅允许 `SelfModule` 写入。针对某个用户的设置项则可以显式列出其主体路径。包中如何表示宿主管理用户类别等部署相关主体，另行确定，不在本设计中暗设全局管理员旁路。

另行明确启用的[宿主调试台](14-inspection-webui.md)可以向受信管理员提供完整配置只读观测。这是宿主控制能力，不通过 Token 名称、普通模块配置接口或 AclTable::check 授予；不会将普通用户、管理员路径或模块隐式提升为 SelfModule。

### 2.1 接口声明与调用

每项 provides 携带 access: AccessPolicy。宿主以 `(对象 Token, 接口路径)` 查到提供方声明，再用可信直接调用主体检查 Access::Call；SelfModule 绑定提供方逻辑对象。普通模块调用的直接主体是实际发起 send/call 的模块，已认证用户直接调用则是该用户。原始发起者继续随请求保留，供明确的代用户管理操作使用，不能被调用主体覆盖。

uses 声明依赖与类型契约，不能替代提供方的 callers。检查在请求接纳前进行；被拒绝的请求不入队、不执行。生命周期限制仍独立成立：create/destroy 即使匹配 callers，也不允许 send/call。

配置与接口分别装载为同一 AclTable 类型的表，宿主按操作入口选表；两个类别中同名的路径不合并、不互相授权。纯查询本身不识别协议、初始化模块或修改 SQLite。

宿主 notifier 以实际登记的事件源主体投递，也检查接收接口的 callers。例如接收 `/core/onebot` 事件的接口可允许该主体；subscriptions 表示接收关系，不绕过 ACL。平台发送者作为已认证事件上下文保留，不因接收接口允许宿主调用而获得宿主权限。宿主原生服务接口同样在其静态接口声明中提供 AccessPolicy。

## 3. 操作边界

| 操作 | 所需权限 |
|---|---|
| send/call 或宿主 notifier 投递接口请求 | 目标接口的调用权 |
| 读取当前值或完整 Entry | 目标项的读取权 |
| 查看路径、Schema、默认值或生成配置表单 | 目标项的读取权 |
| 设置当前值 | 目标项的写入权 |
| 重置为声明默认值 | 目标项的写入权 |
| 列举配置项 | 在宿主过滤，只返回获准读取的项 |
| 批量读取、导出 | 每个返回项均须获准读取；明确指定的批量读取不以部分结果掩盖拒绝 |
| 批量修改 | 每个目标项均须获准写入，全部通过后原子提交 |

上表给出授权边界，不表示所有操作都已进入模块 ABI。本阶段模块配置接口仅为单项 `get/set/reset`；列举、导出及批量操作不因此自动开放，见[宿主接口设计](08-host-interfaces.md)。

上表适用于模块和普通用户配置入口。明确授权的宿主调试台采用独立认证和只读 Inspector，可读取完整配置，不因此获得写入、重置或接口调用能力。

列举的数量与结果应一致，不先返回整表再让 UI 隐藏未授权字段。表单能否编辑还取决于对应写权限，不能仅凭可见就允许修改。

写入只修改当前值，不能改变 Schema、默认值或访问规则。注册、删除实体、挂载声明、导入声明以及替换包属于宿主生命周期或管理操作，不能由某项普通写权限推出。现有 Store 的原生 `register`、`import`、`remove_entity` 不是开放给所有模块的管理接口。

ACL 允许是执行数据操作的必要条件。宿主入口的生命周期限制仍然有效：例如入口被限制为只读时，即使配置声明允许写入，也不能写。只读限制必须沿间接调用传播。

## 4. 来源与跨模块调用

宿主分别记录原始发起者与当前执行模块，不从消息正文、模型输出或来宾参数中读取可信身份。模块收到的自身 Token 只是目标地址，不是可转交的凭证。

对于 `用户 → B → 配置表`：

- B 读取自身运行需要的内部配置，以 B 为访问主体，仍检查目标项声明。
- B 代用户执行配置修改，以被保留的用户为授权主体，检查目标项对该用户的写入声明。不能因 B 拥有内部写权限就把用户操作转换为 B 的自主操作。
- 接口调用许可与目标配置的访问许可分别成立，不能相互替代。

内部配置访问和代用户操作必须由宿主认可的入口契约区分，不能仅凭“目标是否为自身”猜测，也不能由模块在普通参数里随意选择权限更大的身份。具体调用上下文和入口表达方式随 ABI 设计确定，本文不虚构已存在的防代行接口。

群管理员身份不自动成为框架配置权限。群聊正文、引用、召回内容和模型参数不授予权限；Agent 自主操作以其模块主体匹配目标声明，代表用户的明确管理入口保留该用户来源。Bot 与群作用域不能替代身份认证。

## 5. 元数据、存储与热重载

访问规则随插件配置声明提供，由宿主装载后保存在内存中，并绑定稳定模块对象与配置目标。配置 UI 可展示这些规则，但普通配置写入不提供修改 ACL 的能力。

SQLite 保存配置数据；当前落盘的 Schema 和默认值用于表达已保存条目的数据结构，不使数据库成为权限规则的权威。不新增 ACL SQL 表，不把 ACL 塞进可普通写入的配置项，不提供独立的运行中授权增删接口。数据库文件持有者仍可以绕过框架直接访问数据，框架 ACL 不承担操作系统文件隔离。

宿主重启后，在对模块或用户开放配置访问前，先装载对应声明并绑定规则。已有数据库条目没有装载对应声明时，不因数据存在就允许访问，也不重置其值。

热重载保留稳定模块对象身份和已保存配置数据，候选插件持有自己的声明。切换成功前不以候选规则覆盖当前规则；成功交接时将代码、声明及其访问规则一起切换。只替换执行实例且声明相同，不改变权限。

一次配置操作使用同一份已装载的声明。声明切换不能与已经通过检查、尚未提交的写入无序穿插；如何协调跨模块宿主操作、UI 请求与交接暂停点，仍属于运行时排空模型的待定项。这里不引入条目版本、ACL 数据库事务、超时或强制取消。

## 6. 已实现的查询接口

`forest-util::acl` 提供 `Access::{Read, Write, Call}`、`SubjectPattern`、`AccessPolicy`、`AclEntry` 和 `AclTable`。路径段类型沿用 `Token<K>` 的泛型设计，默认是文本 `Segment`，不需要把主体转换成字符串来判定。

宿主用 `AclEntry { entity, key, owner, access }` 表达已绑定的声明：实体和资源路径确定目标，`owner` 独立确定声明所属对象，供 `SelfModule` 匹配。接口表使用目标对象与接口路径，配置表使用实体与配置项路径。该结构不推测实体归属，也不承担宿主身份验证。

`AclTable::new(entries)` 一次性构造完整表，重复键对返回包含实体和配置项的 `DuplicateEntry`，不静默覆盖或合并规则，不返回部分构造的表。`AclTable::default()` 是拒绝全部访问的空表。表没有公开的动态增删改接口。

```rust
let allowed: bool = acl.check(
    &subject, // 宿主提供的真实访问主体
    &entity,  // 目标实体
    &key,     // 目标配置项
    Access::Read,
);
```

接口表查询采用相同参数形式，将资源路径换成接口路径、操作换成 Access::Call。`check` 只借用表和路径，不分配内存、不执行 I/O、不修改规则，直接返回 `bool`；未知对象、未知资源或主体不匹配均为 `false`。它只判定声明的 ACL，不代替来源认证、生命周期限制或数据类型检查。

## 7. 实现职责与未定项

| 部分 | 职责 |
|---|---|
| 插件配置与接口声明 | 提供配置读写主体和接口调用主体；配置另含 Schema 与必填默认值 |
| `forest-util::acl` | 内存表与纯 `check`，根据准确目标、声明所有者、主体和操作返回是否允许 |
| 宿主访问入口 | 装载与绑定声明、提供可信主体、执行 ACL 和生命周期限制 |
| 配置存储 | 校验值并执行 SQLite 原子读写，不认证模块、不推测操作来源 |
| UI | 展示宿主返回的可见配置并提交操作，不承担最终鉴权 |

纯 ACL 类型及查询已在 `forest-util::acl` 实现，外部声明见[Manifest 设计](07-module-manifest.md)，来源上下文、宿主入口和排空交接已接入[运行时](13-runtime-and-sdk.md)。通用代用户认证仍待设计。具体群管理目标等参数约束由相应接口处理，不从配置读写权推导。
