# Forest 控制台使用指南

本文说明当前已实现的界面怎么操作，不要求先读架构设计。界面和模块页签已与运行实例核对；触发策略群选择页更新于 2026-10-19。

文中使用占位符，不记录真实账号、群号或管理地址：`<MANAGEMENT_URL>` 是你的管理入口，`<BOT_ID>` 是框架内的 Bot ID，`<BOT_QQ_ID>` 是机器人 QQ 号，`<GROUP_ID>` 是允许触发的群号。使用时替换为自己部署中的值；管理员凭据由部署者自行保管。

## 第一次进入：先打开当前 Bot

1. 打开本机管理地址 `<MANAGEMENT_URL>`，用管理账号登录，用户名和密码使用部署时设置的管理凭据。
2. 顶部“作用域”选择“部署”。左侧点击 `deployment.bot-catalog`。
3. 右侧切换到 **Bot 运行目录** 页签。第一个与模块 ID 同名的页签是配置编辑器，不是运行目录。
4. 找到要管理的 Bot（下文记为 `<BOT_ID>`），点击 **打开工作区**。
5. 左侧现在显示这个 Bot 的模块。之后查看 Agent、记忆和模型设置，都在这个工作区完成。

如果“打开工作区”不可用，先看这一行的状态：供应应为 `READY`，期望与实际运行状态均应为 `ONLINE`。点击“启动”是提交启动请求，随后点“刷新”查看实际状态。

已在线的 Bot 不需要手动创建任务才会回复。采用 @ 触发策略时，在允许的群 `<GROUP_ID>` 中直接 @ 机器人 `<BOT_QQ_ID>` 即可。同群对话会排队，不同群可以并行。

“部署”管理所有 Bot 的目录、账号和凭据；“Bot 工作区”管理某个 Bot 的模块。Host 是运行这些模块的宿主，它的存储与资源页通常只在运维时使用。切换作用域只是切换管理对象。

## 日常操作去哪里

先按上面的步骤打开 Bot 工作区，再按下表选择左侧模块。

| 想做什么 | 左侧模块 | 进入后操作 |
|---|---|---|
| 修改 Bot 的人格与行为提示词 | `agent.runtime` | **Agent 执行** → **Bot 提示词**：编辑文本，检查计划，再点击外层“应用计划” |
| 看机器人这次为什么没回复 | `agent.runtime` | **Agent 执行** → **执行记录**：输入会话引用后查询，点击一条 Run 看状态、模型回合和工具调用 |
| 查历史记忆、来源群和关联 | `memory.graph` | **多模态记忆** → **来源** / **关系** |
| 测试某段文字或图片能召回什么 | `memory.graph` | **多模态记忆** → **召回试验** |
| 调整上下文保留量与裁剪阈值 | `conversation.scheduler` | **群会话调度** → **上下文预算** |
| 改模型 endpoint、超时、thinking 能力 | `provider.chat-completions` | 当前是 JSON 配置编辑器 |
| 改触发群与 @ 触发规则 | `conversation.trigger-policy` | **对话触发策略**：从 Bot 已加入的群中勾选，再生成并应用计划 |
| 查 OneBot 连接设置 | `adapter.onebot` | **OneBot Adapter** |
| 调整嵌入端点 | `embedding.multimodal` | 当前是 JSON 配置编辑器；模型种类、修订与维度随 Bot 生命周期冻结 |
| 查看或热重载插件 | `component.worker-host` | **组件** |
| 查看持久任务 | `job.scheduler` | **持久任务**；这是模块提交的后台任务，聊天不需要从这里手动发起 |
| 核对发送结果不确定的消息 | `delivery` | **Delivery**；这个页面只列 `UNKNOWN`，不是全部发送历史 |
| 查管理操作记录 | `kernel.audit` | **审计记录** |

启动、停止与重命名 Bot，回到顶部“作用域”选择“部署”，再进入 **Bot 运行目录**。管理员账号在 `deployment.accounts` → **管理账号**；凭据登记在 `deployment.secrets` 的 Secret 管理页签。

## 选择允许触发的群

1. 打开 Bot 工作区 → `conversation.trigger-policy` → **对话触发策略**。
2. 页面从在线 OneBot Adapter 读取已加入的群。Bot 有多个 QQ 账号时，先选择账号；可按群名或群号搜索，群多时点 **下一页**。
3. 勾选允许自动触发的群。翻页、搜索或切换账号不会丢失勾选；展开 **已选 N 个群** 可查看完整集合，并移除当前列表里没显示的旧选择。
4. 选择“仅在 @ Bot 时触发”“每条消息都触发”或“关闭群聊自动触发”，按需设置私聊开关。每条消息都触发可能明显增加模型调用费用。
5. 点击 **生成配置计划**，检查后点击外层 **应用计划**，等待期望配置与生效配置一致。

**刷新群列表** 只重新读取群，不保存配置，也不发送群消息。查询失败时检查 Bot 与 Adapter 是否在线，已有白名单仍会保留。白名单控制的是自动触发 Agent；消息接收、归档和跨群记忆召回各有自己的策略，不由这个开关一并关闭。

## 示例一：查看刚才那次对话

1. 打开当前 Bot 工作区 → `agent.runtime` → **Agent 执行** → **执行记录**。
2. “会话引用”输入 `onebot:group:<GROUP_ID>`，Run 状态先选“全部”，点 **查询**。
3. 点击与消息时间对应的记录。
4. 查看“状态 / 错误”，展开 **模型回合** 和 **工具调用**。必要时点击 **刷新**。

Run 是“一次响应过程”，包括其中的模型和工具步骤；Session 是承载多次响应的会话记录，不是子 Agent。查一次回复通常只需要看 Run。

| 看到的状态 | 怎么理解 |
|---|---|
| `PREPARING_MODEL` | 正在准备模型输入，可能包含记忆召回和图片处理 |
| `MODEL_PENDING` | 模型请求正在等待结算 |
| `WAIT_TOOL` | 正在等待工具结果 |
| `WAIT_APPROVAL` | 工具执行需要批准 |
| `COMPLETED` | Agent 的响应过程结束；平台是否已发出还由 Delivery 负责结算 |
| `FAILED` | 本次响应失败，查看错误码及对应回合 |
| `CANCELLED` | 本次响应已取消 |
| `BLOCKED_UNKNOWN` | 有外部效果尚无法确认结果，需要核对证据 |

`job.scheduler` 中某项任务 `SUCCEEDED` 只说明那项任务成功，不等于机器人已经在群里回复。`delivery` 页面为空只说明没有符合筛选条件的 UNKNOWN 发送，也不能用来判断是否产生过回复。

## 示例二：查一个群的记忆和跨群关系

1. 打开 `memory.graph` → **多模态记忆** → **来源**。
2. 展开 **浏览群主干（实时分页）**，输入群号 `<GROUP_ID>`，点击 **查询主干**。
3. 点击查到的主干，界面会自动填入准确主干 ID 并查询来源。
4. 根据需要增加作者、时间或 TEXT / IMAGE / MIXED 模态筛选。正文筛选至少输入两个字。点 **查询**，更多记录用 **下一页**。
5. 点击一条来源记录，会切到 **关系** 并选中这个节点。点 **一跳列表** 查看直接关系，或点 **多跳区域** 查看周围连接。
6. “全部主干”筛选改为 **跨主干**，可以查看跨群关联；关系详情中的证据用于核对它依据哪条来源、哪个群和作者。

每个 Bot 有一个全局记忆域，每个群对应自己的主干；切换主干是筛选同一个 Bot 的记忆，不是切换数据库。

OneBot 消息正文按整条 CQ 文本保存和召回，@、回复和表情会显示为 CQ 编码；文字中原有的方括号等字符会转义。图片 CQ 中只保存受管引用，实际图片另存为媒体资产并参与 VL 检索，正文中不会展开图片 base64。作者和来源群仍单独显示，不能根据一条 CQ 正文推断消息来自哪个群。

来源默认只查活动且可召回的记录。刚收到、尚在短期上下文中的消息可能还没完成归档；要查已登记但未归档的记录，可展开“更多来源条件”，把“可召回”改成“待归档”。

在 **召回试验** 页输入文字或选择图片，点 **上传并启动试验**，即可看召回证据。它不会向群里发消息，也不会把试验输入写成长期记忆，但会使用真实嵌入服务并消耗相应额度。

## 示例三：修改设置并确认生效

修改人格时，进入 `agent.runtime` → **Agent 执行** → **Bot 提示词**，点击“添加一段”，填写人格、语气或行为要求，点击 **检查提示词计划**，再点击外层 **应用计划**。已有预设会显示在文本框中，可以编辑或移除；全部移除表示清空人格预设。最多 32 段，文档总大小 32 KiB。**核心协议（只读）** 是另一个视图，用来查看该 Agent 插件的固定协议。

有专用界面的模块：修改字段 → 点击模块中的“检查配置计划”或“校验并生成计划” → 点击界面外层的 **应用计划**。

只有通用编辑器的模块：修改“期望配置”中的 JSON → 点击 **预览并应用**。当前这个按钮会依次创建计划并提交，并没有另一个独立的确认窗口。

提交后查看“期望 r…”与“生效 r…”：期望修订表示已保存的目标；生效修订表示运行中的配置。两者相同，且模块处于 `ACTIVE`，才表示该配置已进入运行图。运行中的请求可能需要先结束或排空，因此保存不总是立即生效。

例如 `conversation.trigger-policy` 的字段含义是：

| 字段 | 含义 |
|---|---|
| `allowed_group_ids` | 允许触发的群号列表，群号写成字符串 |
| `group_trigger_mode` | `MENTION` 为 @ 触发，`ALL` 为所有允许群消息触发，`DISABLED` 为关闭群触发 |
| `private_enabled` | 是否启用私聊触发 |

若只希望被 @ 时响应，将允许的群设为 `<GROUP_ID>` 并使用 `MENTION`。JSON 编辑时保留其余现有字段；API Key 使用凭据引用，不在模型配置里直接填写密钥明文。

上下文裁剪阈值在 `conversation.scheduler` 的 **上下文预算** 页；Provider 不负责裁剪。裁剪不调用摘要模型，Bot 静默时也会进行上下文维护。

“历史归档水位”默认 65536 估算 token，“归档后保留”默认 49152；“模型调用总估算 token”默认 98304，包含提示词、工具、召回与输出预留。这些是本地成本策略，供应商的真实上下文容量是另一个限制。超过归档水位会进行归档和视图选择，不会仅因水位超出就拒绝响应。

输出额度只在 `provider.chat-completions` 的 `capabilities.max_output_tokens` 设置，当前实例为 16384；Agent 每次请求读取绑定的 Provider 配置，没有另一份输出额度。启用 thinking 时，供应商计入输出的推理 token 也占用这份额度。已冻结的请求保留原参数，设置用于后续新请求。

## 群聊 Shell 管理员

打开 Bot 工作区 → `shell.command` 的配置页，在 `administrator_principals` 数组中填写 `qq:<QQ_ID>`，将占位符替换为自己的数字 QQ 号；多人分别填写。保留现有 `protocol` 和 `binding_ref`，生成并应用配置计划，等待期望配置与生效配置一致。群聊中的群主或管理员身份不会自动成为框架 Shell 管理员。

在群中发送 `#forest module list` 查看组件，或发送 `#forest jobs list --limit 5` 查看任务；可选在命令前 @ Bot。命令直接进入管理通道，不调用 LLM。正文与记忆仍保存完整 CQ，Shell 控制输入独立保存并证明来源。

`core` 救援权限在 `kernel.runtime` 的 **群聊 Core 救援授权** 单独设置，按 Bot 绑定、群、QQ 主体与动作授权，不继承普通 Shell 管理员名单。

## Agent 的联网与 OneBot 工具

这组工具是独立安装的 `tools.deepseek-web`、`tools.http`、`tools.onebot`，不属于 Agent 本体。安装后在 Bot 工作区选中对应组件，即可打开各包自己的设置页；配置仍使用“生成配置计划 → 应用计划”。发行安装步骤见 [外部插件说明](../plugins/README.md)。

DeepSeek 设置 API 根地址、Secret 引用和结果上限。HTTP 设置允许访问的目标及允许写操作的主体。OneBot 设置页可以选择当前账号已加入的群，并为发送、禁言、踢人、名片和群名分别选择允许的群角色；它的群范围独立于“对话触发策略”。私聊发送需全局操作者权限。

发送工具返回“已入队”后，Delivery 才负责实际发送；Agent 可用 `onebot_delivery_status` 核对结果。`UNKNOWN` 表示无法确认外部结果，不能靠重新调用禁言、踢人或发送来假装恢复。

## 热重载、启停和删除的区别

在 `component.worker-host` → **组件** 中选择活动组件，点 **查看**，再点 **提交重载**，可以请求当前选定工件换代。它不会自动把磁盘上修改过的 Python 文件当作新插件；发布新代码需要先登记新包，再走候选图预检与包选择。

**停止 Bot** 保留身份、配置和记忆，之后可启动。部署中的 **Bot 退役** 是删除流程，不等同于停止。记忆的 **遗忘** 也是真正删除相应内容，需要先查看影响计划再执行。

## 当前界面尚不完善的地方

- 左侧模块 ID 仍是技术名称；同名默认页签常常只是配置编辑器，具体功能在旁边的中文页签。
- Provider、Shell 管理员、Embedding 等设置还没有专用运行期表单，目前需要在 WebUI 编辑 JSON；触发群已有专用选择页。
- Delivery 的界面目前只处理 UNKNOWN 核对，尚不是可按群检索全部成功/失败发送的日志页面。

这些是当前操作界面的缺口，不能靠阅读架构文档解决。设计和实际验证分别见[设计索引](README.md)、[实现状态](implementation-status.md)；部署启动和故障恢复见[运行手册](operations-clean-production-launch.md)。
