# P3 Agent 运行切片

本文记录当前代码中的持久 Agent、模型传输与 Web 配置实现。定时任务、子 Agent、多主干长期记忆和完整群聊管理 Shell 仍属于首版剩余工作，不能由本切片的通过结果推断已经实现。

## 配置与使用

在 WebUI 创建 Bot 后，进入「Agent 与模型」。配置 Chat Completions 兼容 API 基础地址、模型名称、API 密钥、人格、模型能力与预算，预览后保存。地址需要包含服务所要求的基础路径，例如 `/v1`；客户端追加 `/chat/completions`。不自动发送付费连通性探测。支持无密钥的明确本地端点。

随后将 OneBot 账号的回复模式设为「Agent 对话」，启用连接并配置触发规则。所有群消息照常持久化；模型仅因明确触发或当前工具链的继续执行而调用。不同 Bot 使用不同的专用数据库、配置、密钥和每日预算；同一 Bot 的不同群各自拥有串行前台会话，并公平共享执行容量。

关闭「模型支持图片输入」只影响调用 API 时的输入投影。原始上下文和图片引用不因此丢失。图片来源需要在后台逐项允许 HTTP origin；图片会按绑定来源抓取并校验，默认不允许下载。流式响应和流式用量字段可分别关闭；输出限制参数可以选择 `max_tokens` 或 `max_completion_tokens`，以匹配实际端点。

配置提交采用短效管理票据、不可变计划、预期 revision 和幂等 operation ID。密钥在宿主加密保管，页面只显示是否已保存；计划和审计不保存明文密钥。普通配置变化和 Binding 回复模式切换供新 Run 使用，已有 Run 保留其冻结 Agent 配置；停用 Agent、轮换密钥、撤销 Bot policy 或工具授权，会阻止已有 Run 的后续许可与状态提交。最终答案尚未提交时发生明确配置撤销，会终结该 Run 并保留原步骤事实，不再发送答案；结果未知时仍需核实或显式取消。

## 会话与安全点

一个群聊的 `Conversation` 最多持有一个活动 `Session`，该 Session 最多持有一个前台 `Run`。群调度器只执行一个有界 quantum；等待审批、输入或未知结果时可以归还物理执行槽，但不会据此释放群会话。另一个群仍可取得执行容量。

每个模型步骤分别持久化所选输入、逻辑步骤身份、请求 manifest、传输尝试和结果。模型请求前，事务验证上一组工具调用已经全部闭合，先把完整的 assistant/tool 组作为一个不可拆裁剪单位发布，再接入截至最新待处理触发记录的消息前缀。若没有新触发，工具链继续调用模型时不会吸入其后的普通消息。

模型返回最终答案后先记录 `FINAL_READY`，随后以该步骤固定的 `input_revision` 提交最终回复和发送意图。此时到来的新触发留待后续串行 Run，不能修改正在提交的答案来源。没有后续触发时，剩余普通消息静默进入短期上下文并排空；不会发起总结或额外模型调用。输入作者保留稳定主体、平台用户 ID、显示名、群来源和匿名身份来源，不按显示名合并用户。

`MessageStore` 的安全点与结束操作对已注册 Agent Run 禁止通用路径绕过，AgentStore 在同一数据库事务中执行相应辅助操作。checkpoint 和请求快照不可变；Actor、Host、Binding、Session、policy、storage 和 owner epoch 共同限制迟到写入。

## 工具与审批

管理员在 WebUI 配置允许的工具，映射到已经安装的本 Bot 组件服务。每个工具固定服务契约、输入 schema、包摘要与契约摘要。模型仅能从当前工具目录选择名称，并在参数包装中明确给出一个本 Run 已接纳触发消息的 `authority_trigger_id`；模型不能自行传入授权主体。

`authority=trigger` 依据该触发主体执行明确开放的工具；`binding_admin` 还要求来源是当前 Binding 配置中的真实管理员账号，拒绝匿名和 Bot 自消息。多个触发消息不会合并出一个权限更大的主体。审批针对具体参数摘要、触发、主体、policy 与期限，审批通过后仍重新检查当前权限。

工具意图先保存，实际执行使用固定 operation ID。Kernel 接纳根调用时校验该工具意图、冻结服务与输入、包身份；根调用及所有子调用继承同一个 `agent_tool_id`。组件状态读写、调用完成和子调用接纳的最终事务继续复核 Agent 授权。标为 `effect=read` 的工具无法通过状态 SDK 写入组件状态。此约束不构成 Python 插件的操作系统沙箱，插件仍须可信。

后台可以批准/拒绝具体工具、取消所显示 checkpoint 的 Run，或为未知工具登记已核实的成功/失败结果。取消终结当前 Run、撤销旧 Actor 后续写入，并保留已有外部副作用及未知成本；它不声称撤销已到达外部服务的请求。未知工具只有获得可信 Kernel 完成回执或管理员明确核实后才能继续，不能自动分配新 operation ID 重放。

## 模型尝试、成本与多模态投影

语义 manifest 固定 Bot/Run/step、输入切口、来源单元、模型能力、序列化版本和媒体修订；传输尝试另存实际请求体与摘要。发送前核对精确请求与短效许可。HTTP/SSE 解析限制响应总量、事件大小、工具数量与参数大小；完整收集后才接纳结果，网络层不自动重放请求。

每次尝试在 Bot 数据库中预留每日 token 预算，并限制单 Run 的步骤数与期限。已确认没有发出的尝试可以释放预留并按原始语义请求恢复；未知结果保留预算与阻塞状态，不能因本地取消、连接断开或等待超时而假设没有费用。已返回用量按实际记录结算；未返回用量时保留保守成本。预算是本地许可与核算机制，不保证外部 Provider 的报价、计费或图片 token 估算与管理员填写的参数一致。

支持文本和图片模型输入。视觉请求只使用已验证且来源绑定的 `MediaSnapshot`，编码实际图片字节；文本模型在所有消息角色、工具结果及嵌套引用中递归移除图片/媒体内容，保留可读文本、作者、群来源与诚实的不可见说明。纯图片触发不会伪造图片描述，也不会作为空白输入被静默标成已回答。原始多模态单元保持不变。

当前自动抓取只授权本 Bot、当前群会话、输入切口内且仍可读的直接 Inbox 图片，精确核对 unit/event/part 绑定。工具、引用及跨群长期记忆的图片自动抓取仍需后续接入，当前 Web 配置不启用工具图片映射。原图限制为 8 MiB、累计解码像素 16,777,216、100 帧；一次 materialize 最多 32 个引用、返回 32 MiB，抓取窗口最多 15 秒并受 Run 剩余期限限制。每 Bot 原图总配额 512 MiB，提交与配额占用在同一事务内串行核验。图片回收与配额调整尚待管理功能接入。GIF/WebP 原件完整保留，但不保证实际模型端点能理解动画中的全部帧。

上下文裁剪完全在本地进行，不调用摘要模型。触发消息和当前工具因果组受到保护；超过硬预算时明确失败，不能拆掉半组工具或隐藏当前触发来强行发送。归档保存精确来源单元引用，避免用最小/最大序号区间把未裁剪记录错误标成已归档。

## 可执行验证与剩余边界

- `tests/test_agent_config.py`：真实 PostgreSQL 的配置 CAS、并发提交、幂等重放、密钥保留/轮换及输入约束。
- `tests/test_models.py`：真实 TCP HTTP/SSE 分片、工具结果、超时/取消、来源与图文投影。
- `tests/test_media.py`：真实 HTTP 抓取与 PostgreSQL 不可变存储、抓取期间撤权、并发配额、格式/像素上限、取消与重启缓存。
- `tests/test_agent_runner.py`、`tests/test_web_agent.py`：持久步骤、原生 Worker、Web 配置、OneBot 与模型 HTTP 纵向接通、跨群并行与同群切口。
- `scripts/smoke_agent_panel.py`：真实浏览器的配置、审批、草稿与 Bot 切换竞态、移动布局；API 响应受控，不代表真实外部模型验收。

最终全量结果以[实现状态与验证记录](implementation-status.md)为准。当前没有真实 QQ、LLM 或 Embedding 凭据的上线联调结论。P4 还需要完整多主干图文记忆、嵌入/召回、跨主干出处与遗忘屏障；当前媒体抓取不等于完成多模态长期记忆。P3 的通用定时任务和子 Agent、P5 的完整权限/群聊管理/运维面板仍需继续实现和验证。
